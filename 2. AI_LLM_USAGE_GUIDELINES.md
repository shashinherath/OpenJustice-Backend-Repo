# 1️⃣ AI & LLM Usage Guidelines

## 📋 Purpose

Control how Large Language Models (LLMs) are used to ensure **accuracy**, **ethics**, **reproducibility**, and **cost efficiency** in the OpenJustice legal assistance platform.

---

## 🎯 Core Principles

1. **Centralized Access** - All LLM calls go through a dedicated service
2. **Version Control** - Track model versions and prompt changes
3. **Anti-Hallucination** - Enforce citation requirements
4. **Ethical AI** - Neutral, unbiased responses
5. **Cost Control** - Monitor and limit token usage

---

## 🏗️ Architecture Rules

All LLM interactions must go through a single centralized service layer. This ensures consistent logging, error handling, cost tracking, and version control across the entire application. Never make direct API calls from controllers or routes—always use the dedicated LLMService.

### ✅ DO: Centralized LLM Service

```python
# ✅ CORRECT: Use LLMService
# app/services/llm_service.py
from openai import AsyncOpenAI
from app.core.logging import logger
from app.config import settings

class LLMService:
    """Centralized LLM access point"""

    def __init__(self):
        self.client = AsyncOpenAI(api_key=settings.OPENAI_API_KEY)
        self.model = settings.OPENAI_MODEL
        self.max_tokens = settings.MAX_COMPLETION_TOKENS

    async def generate_response(
        self,
        prompt: str,
        system_message: str,
        temperature: float = 0.3,
        **kwargs
    ) -> dict:
        """Generate LLM response with logging"""
        logger.info(f"LLM Request - Model: {self.model}, Temp: {temperature}")

        try:
            response = await self.client.chat.completions.create(
                model=self.model,
                messages=[
                    {"role": "system", "content": system_message},
                    {"role": "user", "content": prompt}
                ],
                temperature=temperature,
                max_tokens=self.max_tokens,
                **kwargs
            )

            # Log usage for cost tracking
            usage = response.usage
            logger.info(f"Token Usage - Input: {usage.prompt_tokens}, "
                       f"Output: {usage.completion_tokens}, "
                       f"Total: {usage.total_tokens}")

            return {
                "content": response.choices[0].message.content,
                "model": response.model,
                "usage": usage,
                "finish_reason": response.choices[0].finish_reason
            }

        except Exception as e:
            logger.error(f"LLM Generation Error: {str(e)}")
            raise
```

## 📝 Prompt Versioning & Template Management

Prompts must be versioned and stored centrally, never hardcoded in services or controllers. This enables A/B testing, rollback capabilities, and reproducibility of AI outputs. Each prompt version should be tracked with metadata including author, date, and changes made.

### Prompt Template Storage

```python
# app/prompts/__init__.py
"""Centralized prompt templates with versioning"""

LEGAL_ASSISTANT_SYSTEM_V1 = """You are a legal assistant for Sri Lankan law.

STRICT RULES:
1. Only answer questions about Sri Lankan law
2. Always cite sources with [Source: Act Name, Section X]
3. If uncertain, say "I don't have enough information"
4. Never provide legal advice - only legal information
5. Maintain neutral, professional tone

Available context: {context}
User language: {language}
"""

LEGAL_ASSISTANT_SYSTEM_V2 = """You are a legal information assistant specializing in Sri Lankan law.

MANDATORY REQUIREMENTS:
- Cite all information: [Source: Act Name, Section X]
- Respond in user's language: {language}
- Differentiate between facts and interpretations
- Include confidence level: [Confidence: High/Medium/Low]
- For complex queries, suggest consulting a lawyer

Context: {context}
"""

# Version mapping
PROMPT_VERSIONS = {
    "legal_assistant": {
        "v1": LEGAL_ASSISTANT_SYSTEM_V1,
        "v2": LEGAL_ASSISTANT_SYSTEM_V2,
        "default": "v2"  # Current production version
    }
}

def get_prompt(template_name: str, version: str = None) -> str:
    """Get versioned prompt template"""
    template_versions = PROMPT_VERSIONS.get(template_name)
    if not template_versions:
        raise ValueError(f"Unknown template: {template_name}")

    version = version or template_versions["default"]
    return template_versions[version]
```

## 🛡️ Anti-Hallucination Rules

LLMs can generate plausible-sounding but incorrect information (hallucinations). For legal applications, this is unacceptable. Implement multiple validation layers including mandatory citations, confidence scoring, and context grounding checks to ensure all responses are factually anchored to source documents.

### Rule 1: Citation Enforcement

Every factual claim in an LLM response must be traceable to a source document. Validate that citations exist and match the retrieved documents. Reject responses that lack proper citations or reference documents not provided in the context.

```python
def validate_response_citations(response: str, retrieved_docs: list) -> dict:
    """Ensure response contains proper citations"""

    # Check for citation markers
    citation_pattern = r'\[Source:.*?\]'
    citations = re.findall(citation_pattern, response)

    if not citations:
        logger.warning("Response missing citations - REJECTED")
        return {
            "valid": False,
            "error": "NO_CITATIONS",
            "message": "Response must include source citations"
        }

    # Verify citations match retrieved documents
    doc_sources = {doc.metadata['source'] for doc in retrieved_docs}

    for citation in citations:
        # Extract source from citation
        source = extract_source_name(citation)
        if source not in doc_sources:
            logger.warning(f"Invalid citation: {citation}")
            return {
                "valid": False,
                "error": "INVALID_CITATION",
                "message": f"Citation '{citation}' not found in retrieved documents"
            }

    return {"valid": True, "citations": citations}
```

### Rule 2: Confidence Scoring

Use the LLM to self-assess its confidence level in the generated response. This meta-cognitive approach helps identify uncertain answers that may require human review or additional context. Low confidence responses should be flagged or require manual approval.

```python
async def generate_with_confidence(self, query: str, context: str) -> dict:
    """Generate response with confidence assessment"""

    # First pass: Generate answer
    response = await self.llm_service.generate_response(
        prompt=query,
        system_message=self.get_legal_prompt(context),
        temperature=0.2
    )

    # Second pass: Self-assessment
    assessment_prompt = f"""Rate the confidence of this answer (High/Medium/Low):

Question: {query}
Answer: {response['content']}
Context: {context}

Provide confidence level and reasoning."""

    assessment = await self.llm_service.generate_response(
        prompt=assessment_prompt,
        system_message="You are a legal accuracy assessor.",
        temperature=0.1
    )

    return {
        "answer": response['content'],
        "confidence": extract_confidence(assessment['content']),
        "reasoning": assessment['content']
    }
```

### Rule 3: Context Grounding Check

Verify that the LLM's response is grounded in the provided context rather than relying on its pre-trained knowledge. Extract key claims from the response and verify each one can be supported by the context documents. Responses with low grounding ratios should be rejected.

```python
def verify_context_grounding(response: str, context: str) -> bool:
    """Ensure response is grounded in provided context"""

    # Extract key claims from response
    claims = extract_claims(response)

    # Check each claim against context
    grounded_claims = 0
    for claim in claims:
        if is_supported_by_context(claim, context):
            grounded_claims += 1

    grounding_ratio = grounded_claims / len(claims) if claims else 0

    if grounding_ratio < 0.8:  # 80% threshold
        logger.warning(f"Low grounding ratio: {grounding_ratio:.2f}")
        return False

    return True
```

## 📊 Model Version Logging

Log every LLM request with complete metadata including model version, prompt version, parameters, tokens used, and response time. This creates an audit trail for reproducibility, debugging, and compliance. If a user reports an issue, you should be able to reproduce the exact response by looking up the logged request.

### Track Model Usage

```python
# app/models/llm_request.py
from sqlalchemy import Column, Integer, String, DateTime, JSON, Float
from datetime import datetime

class LLMRequest(Base):
    """Log every LLM request for reproducibility"""
    __tablename__ = "llm_requests"

    id = Column(Integer, primary_key=True)
    request_id = Column(String(36), unique=True, index=True)
    user_id = Column(Integer, index=True)

    # Model details
    model_name = Column(String(100), nullable=False)
    model_version = Column(String(50))
    prompt_version = Column(String(50))

    # Request/Response
    system_message = Column(String, nullable=False)
    user_prompt = Column(String, nullable=False)
    response_text = Column(String)

    # Metadata
    temperature = Column(Float)
    max_tokens = Column(Integer)
    prompt_tokens = Column(Integer)
    completion_tokens = Column(Integer)
    total_tokens = Column(Integer)

    # Timing
    created_at = Column(DateTime, default=datetime.utcnow)
    response_time_ms = Column(Integer)

    # Status
    status = Column(String(20))  # success, error, timeout
    error_message = Column(String)
```

### Logging Implementation

Implement comprehensive logging at the service layer to capture every LLM interaction. Include timing metrics, token counts, and error details. Store logs in the database for long-term analysis and audit trails, not just in application logs.

```python
async def generate_response_with_logging(
    self,
    prompt: str,
    system_message: str,
    user_id: int,
    **kwargs
) -> dict:
    """Generate response with full audit trail"""

    request_id = str(uuid.uuid4())
    start_time = time.time()

    try:
        response = await self.client.chat.completions.create(
            model=self.model,
            messages=[
                {"role": "system", "content": system_message},
                {"role": "user", "content": prompt}
            ],
            **kwargs
        )

        response_time_ms = int((time.time() - start_time) * 1000)

        # Log to database
        await self.log_llm_request(
            request_id=request_id,
            user_id=user_id,
            model_name=self.model,
            system_message=system_message,
            user_prompt=prompt,
            response_text=response.choices[0].message.content,
            prompt_tokens=response.usage.prompt_tokens,
            completion_tokens=response.usage.completion_tokens,
            total_tokens=response.usage.total_tokens,
            response_time_ms=response_time_ms,
            status="success"
        )

        return response

    except Exception as e:
        # Log error
        await self.log_llm_request(
            request_id=request_id,
            user_id=user_id,
            model_name=self.model,
            system_message=system_message,
            user_prompt=prompt,
            status="error",
            error_message=str(e)
        )
        raise
```

## 💰 Token Usage Limits

LLM API calls are expensive and can be abused. Implement per-user and per-request token limits to control costs and prevent denial-of-service scenarios. Track usage in real-time using Redis cache for fast lookups, with database persistence for billing and analytics.

### Rate Limiting Configuration

```python
# app/config.py
class Settings(BaseSettings):
    # Token limits
    MAX_PROMPT_TOKENS: int = 4000
    MAX_COMPLETION_TOKENS: int = 1000
    MAX_TOKENS_PER_USER_PER_DAY: int = 50000
    MAX_TOKENS_PER_REQUEST: int = 5000

    # Cost tracking
    COST_PER_1K_INPUT_TOKENS: float = 0.01
    COST_PER_1K_OUTPUT_TOKENS: float = 0.03
    DAILY_COST_ALERT_THRESHOLD: float = 100.0
```

### Token Usage Tracking

Track token usage at both the user and system levels. Use Redis for fast real-time checks and PostgreSQL for persistent storage and analytics. Implement daily limits per user and alert when cost thresholds are exceeded.

```python
class TokenUsageTracker:
    """Track and limit token usage"""

    def __init__(self, db: AsyncSession, cache: Redis):
        self.db = db
        self.cache = cache

    async def check_user_limit(self, user_id: int) -> dict:
        """Check if user has exceeded daily token limit"""
        cache_key = f"token_usage:{user_id}:{date.today()}"

        # Get from cache
        usage = await self.cache.get(cache_key)
        if usage is None:
            # Get from database
            usage = await self.get_daily_usage_from_db(user_id)
            await self.cache.set(cache_key, usage, ex=86400)  # 24h

        usage = int(usage)
        limit = settings.MAX_TOKENS_PER_USER_PER_DAY

        return {
            "usage": usage,
            "limit": limit,
            "remaining": max(0, limit - usage),
            "exceeded": usage >= limit
        }

    async def increment_usage(self, user_id: int, tokens: int):
        """Increment user's token usage"""
        cache_key = f"token_usage:{user_id}:{date.today()}"
        await self.cache.incrby(cache_key, tokens)

        # Log to database
        await self.log_token_usage(user_id, tokens)

    async def estimate_cost(self, prompt_tokens: int, completion_tokens: int) -> float:
        """Calculate request cost"""
        input_cost = (prompt_tokens / 1000) * settings.COST_PER_1K_INPUT_TOKENS
        output_cost = (completion_tokens / 1000) * settings.COST_PER_1K_OUTPUT_TOKENS
        return round(input_cost + output_cost, 4)
```

### Pre-Request Validation

Validate token limits before making the LLM API call to fail fast and provide clear error messages. Estimate prompt token count and check against both per-request and daily user limits. Update usage counters immediately after successful requests.

```python
async def generate_with_limits(
    self,
    prompt: str,
    user_id: int,
    **kwargs
) -> dict:
    """Generate response with token limit checks"""

    # Check user's daily limit
    usage_status = await self.token_tracker.check_user_limit(user_id)

    if usage_status["exceeded"]:
        raise TokenLimitExceeded(
            f"Daily token limit reached: {usage_status['limit']} tokens"
        )

    # Estimate prompt tokens
    estimated_prompt_tokens = len(prompt.split()) * 1.3  # Rough estimate

    if estimated_prompt_tokens > settings.MAX_PROMPT_TOKENS:
        raise ValidationException(
            f"Prompt too long: {estimated_prompt_tokens} tokens "
            f"(max: {settings.MAX_PROMPT_TOKENS})"
        )

    # Generate response
    response = await self.llm_service.generate_response(
        prompt=prompt,
        user_id=user_id,
        max_tokens=settings.MAX_COMPLETION_TOKENS,
        **kwargs
    )

    # Update usage
    total_tokens = response['usage'].total_tokens
    await self.token_tracker.increment_usage(user_id, total_tokens)

    # Calculate cost
    cost = await self.token_tracker.estimate_cost(
        response['usage'].prompt_tokens,
        response['usage'].completion_tokens
    )

    logger.info(f"Request cost: ${cost:.4f} | User: {user_id}")

    return response
```
