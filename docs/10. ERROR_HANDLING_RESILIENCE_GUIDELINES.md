# 9️⃣ Error Handling & Resilience Guidelines

## 📋 Purpose

Standardize **failure behavior** across the OpenJustice platform. Implement AI provider fallbacks, timeout strategies, circuit breakers, and graceful degradation for reliable service delivery.

---

## 🎯 Core Principles

1. **Fail Fast** - Detect errors quickly
2. **Fail Safe** - Degrade gracefully
3. **Fail Transparently** - Inform users appropriately
4. **Recovery** - Automatic retry with backoff
5. **Monitoring** - Track failure patterns

## 🤖 AI Provider Failure Fallback

LLM providers can experience outages, rate limiting, or degraded performance. Implement fallback chains to automatically switch to backup providers when the primary fails. Maintain provider health status and prefer healthy providers. Never rely on a single AI provider for critical functionality.

### Provider Chain Strategy

```python
# app/services/llm/provider_chain.py
from typing import List, Optional
from abc import ABC, abstractmethod

class LLMProvider(ABC):
    """Base class for LLM providers"""

    @abstractmethod
    async def generate(self, prompt: str, **kwargs) -> dict:
        pass

    @abstractmethod
    def is_available(self) -> bool:
        pass

class OpenAIProvider(LLMProvider):
    """OpenAI GPT-4 provider"""

    async def generate(self, prompt: str, **kwargs) -> dict:
        # OpenAI API call
        pass

    def is_available(self) -> bool:
        # Check if API key is configured
        return bool(settings.OPENAI_API_KEY)

class AnthropicProvider(LLMProvider):
    """Anthropic Claude provider (fallback)"""

    async def generate(self, prompt: str, **kwargs) -> dict:
        # Anthropic API call
        pass

    def is_available(self) -> bool:
        return bool(settings.ANTHROPIC_API_KEY)

class LLMProviderChain:
    """Fallback chain for LLM providers"""

    def __init__(self):
        # Primary → Secondary → Tertiary
        self.providers: List[LLMProvider] = [
            OpenAIProvider(),
            AnthropicProvider(),
            # Add more fallbacks as needed
        ]

    async def generate_with_fallback(
        self,
        prompt: str,
        max_retries_per_provider: int = 2,
        **kwargs
    ) -> dict:
        """Generate with automatic fallback"""

        last_error = None

        for provider in self.providers:
            if not provider.is_available():
                logger.warning(f"Provider {provider.__class__.__name__} not available")
                continue

            provider_name = provider.__class__.__name__

            for attempt in range(max_retries_per_provider):
                try:
                    logger.info(f"Attempting generation with {provider_name} (attempt {attempt + 1})")

                    result = await provider.generate(prompt, **kwargs)

                    logger.info(f"Generation successful with {provider_name}")
                    return {
                        **result,
                        "provider": provider_name,
                        "attempt": attempt + 1
                    }

                except Exception as e:
                    last_error = e
                    logger.warning(f"{provider_name} attempt {attempt + 1} failed: {e}")

                    if attempt < max_retries_per_provider - 1:
                        # Exponential backoff
                        wait_time = 2 ** attempt
                        await asyncio.sleep(wait_time)

        # All providers failed
        logger.error("All LLM providers failed")
        raise LLMProviderException(
            f"All LLM providers exhausted. Last error: {str(last_error)}"
        )

llm_provider_chain = LLMProviderChain()
```

## ⏱️ Timeout Strategies

Define appropriate timeout values for different service types. LLM calls may take 5-30 seconds, database queries should complete in milliseconds, and external APIs vary. Always set timeouts to prevent hanging requests from exhausting system resources. Use progressive timeouts—shorter for retries, longer for initial attempts.

### Service-Level Timeouts

### Timeout Implementation

Implement timeouts using async context managers or timeout decorators. Ensure proper cleanup when timeouts occur. Log timeout events for monitoring and capacity planning. Distinguish between network timeouts and processing timeouts.

```python
# app/core/timeout_handler.py
import asyncio
from functools import wraps

class TimeoutException(Exception):
    """Raised when operation times out"""
    pass

def with_timeout(seconds: float):
    """Decorator to add timeout to async functions"""

    def decorator(func):
        @wraps(func)
        async def wrapper(*args, **kwargs):
            try:
                return await asyncio.wait_for(
                    func(*args, **kwargs),
                    timeout=seconds
                )
            except asyncio.TimeoutError:
                logger.error(f"Timeout after {seconds}s: {func.__name__}")
                raise TimeoutException(
                    f"Operation timed out after {seconds} seconds"
                )

        return wrapper

    return decorator

# Usage example
@with_timeout(30)
async def generate_llm_response(prompt: str) -> str:
    """Generate response with timeout"""
    response = await llm_client.generate(prompt)
    return response
```

### Context Manager for Timeouts

Use context managers to enforce timeouts cleanly with automatic resource cleanup. This ensures timeout logic is consistent and prevents resource leaks when operations are cancelled.

```python
class TimeoutContext:
    """Context manager for timeouts"""

    def __init__(self, seconds: float, operation_name: str):
        self.seconds = seconds
        self.operation_name = operation_name

    async def __aenter__(self):
        self.start_time = asyncio.get_event_loop().time()
        logger.debug(f"Starting {self.operation_name} with {self.seconds}s timeout")
        return self

    async def __aexit__(self, exc_type, exc_val, exc_tb):
        elapsed = asyncio.get_event_loop().time() - self.start_time

        if elapsed > self.seconds:
            logger.warning(f"{self.operation_name} took {elapsed:.2f}s (timeout: {self.seconds}s)")
        else:
            logger.debug(f"{self.operation_name} completed in {elapsed:.2f}s")

        return False

# Usage
async def process_query(query: str):
    async with TimeoutContext(30, "LLM Generation"):
        response = await llm_service.generate(query)
    return response
```

## 🔌 Circuit Breaker Pattern

Circuit breakers prevent cascading failures by temporarily blocking requests to failing services. When a service exceeds its failure threshold, the circuit breaker "opens" and fast-fails subsequent requests without attempting the call. After a cooldown period, it tries again. This protects both your system and the failing service from overload.

### Circuit Breaker Implementation

```python
# app/core/circuit_breaker.py
from enum import Enum
from datetime import datetime, timedelta

class CircuitState(Enum):
    CLOSED = "closed"  # Normal operation
    OPEN = "open"  # Failures exceeded, reject requests
    HALF_OPEN = "half_open"  # Testing if service recovered

class CircuitBreaker:
    """Lightweight circuit breaker for external services"""

    def __init__(
        self,
        failure_threshold: int = 5,
        recovery_timeout: int = 60,
        expected_exception: type = Exception
    ):
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.expected_exception = expected_exception

        self.failure_count = 0
        self.last_failure_time = None
        self.state = CircuitState.CLOSED

        self._lock = asyncio.Lock()

    async def call(self, func, *args, **kwargs):
        """Execute function with circuit breaker protection"""

        async with self._lock:
            # Check circuit state
            if self.state == CircuitState.OPEN:
                # Check if recovery timeout has passed
                if self._should_attempt_reset():
                    logger.info("Circuit breaker: Attempting reset (HALF_OPEN)")
                    self.state = CircuitState.HALF_OPEN
                else:
                    raise CircuitBreakerOpenException(
                        f"Circuit breaker is OPEN. Service unavailable."
                    )

        # Attempt call
        try:
            result = await func(*args, **kwargs)

            # Success - reset circuit
            async with self._lock:
                if self.state == CircuitState.HALF_OPEN:
                    logger.info("Circuit breaker: Reset successful (CLOSED)")
                    self.state = CircuitState.CLOSED
                    self.failure_count = 0

            return result

        except self.expected_exception as e:
            # Failure - increment counter
            async with self._lock:
                self.failure_count += 1
                self.last_failure_time = datetime.utcnow()

                if self.failure_count >= self.failure_threshold:
                    logger.error(f"Circuit breaker: Threshold exceeded, opening circuit")
                    self.state = CircuitState.OPEN

                logger.warning(
                    f"Circuit breaker: Failure {self.failure_count}/{self.failure_threshold} "
                    f"(state: {self.state.value})"
                )

            raise

    def _should_attempt_reset(self) -> bool:
        """Check if enough time has passed to attempt reset"""
        if self.last_failure_time is None:
            return True

        elapsed = (datetime.utcnow() - self.last_failure_time).total_seconds()
        return elapsed >= self.recovery_timeout

    def get_state(self) -> dict:
        """Get circuit breaker status"""
        return {
            "state": self.state.value,
            "failure_count": self.failure_count,
            "last_failure": self.last_failure_time.isoformat() if self.last_failure_time else None
        }

# Global circuit breakers
llm_circuit_breaker = CircuitBreaker(
    failure_threshold=5,
    recovery_timeout=60,
    expected_exception=LLMException
)

database_circuit_breaker = CircuitBreaker(
    failure_threshold=3,
    recovery_timeout=30,
    expected_exception=DatabaseException
)
```

### Using Circuit Breaker

Wrap calls to external services (LLMs, databases, APIs) with circuit breakers. Configure appropriate failure thresholds and recovery times based on service characteristics. Monitor circuit breaker state changes as indicators of service health.

```python
async def call_llm_with_circuit_breaker(prompt: str) -> str:
    """Call LLM with circuit breaker protection"""

    try:
        response = await llm_circuit_breaker.call(
            llm_service.generate,
            prompt=prompt
        )
        return response

    except CircuitBreakerOpenException as e:
        logger.error(f"LLM service unavailable: {e}")

        # Return fallback response
        return get_fallback_response()
```

## 🔄 Graceful Degradation

When components fail, degrade functionality gracefully rather than showing errors. Provide cached responses, simplified results, or manual fallbacks. Inform users about degraded functionality transparently. The system should remain partially functional even when non-critical components fail.

### Feature Degradation Levels

```python
# app/core/degradation.py
from enum import IntEnum

class DegradationLevel(IntEnum):
    """Service degradation levels"""
    FULL = 0  # All features available
    PARTIAL = 1  # Some features disabled
    MINIMAL = 2  # Only essential features
    MAINTENANCE = 3  # Read-only mode

class ServiceDegradationManager:
    """Manage service degradation"""

    def __init__(self):
        self.current_level = DegradationLevel.FULL
        self._lock = asyncio.Lock()

    async def set_degradation_level(self, level: DegradationLevel):
        """Set degradation level"""
        async with self._lock:
            old_level = self.current_level
            self.current_level = level

            logger.warning(
                f"Service degradation changed: {old_level.name} → {level.name}"
            )

    def is_feature_available(self, feature: str) -> bool:
        """Check if feature is available at current degradation level"""

        # Feature availability by degradation level
        feature_levels = {
            "chat": DegradationLevel.FULL,
            "document_upload": DegradationLevel.FULL,
            "voice_input": DegradationLevel.PARTIAL,
            "voice_output": DegradationLevel.PARTIAL,
            "translation": DegradationLevel.PARTIAL,
            "search": DegradationLevel.MINIMAL,
            "health_check": DegradationLevel.MAINTENANCE
        }

        required_level = feature_levels.get(feature, DegradationLevel.FULL)

        available = self.current_level <= required_level

        if not available:
            logger.info(
                f"Feature '{feature}' unavailable at degradation level {self.current_level.name}"
            )

        return available

    async def auto_adjust_degradation(self):
        """Automatically adjust based on system health"""

        # Check system metrics
        llm_health = await check_llm_health()
        db_health = await check_database_health()

        if not llm_health and not db_health:
            await self.set_degradation_level(DegradationLevel.MAINTENANCE)
        elif not llm_health:
            await self.set_degradation_level(DegradationLevel.MINIMAL)
        elif db_health < 0.5:  # Less than 50% capacity
            await self.set_degradation_level(DegradationLevel.PARTIAL)
        else:
            await self.set_degradation_level(DegradationLevel.FULL)

degradation_manager = ServiceDegradationManager()
```

### Feature-Level Degradation

Implement feature flags or configuration to control degradation behavior. Disable non-essential features when system load is high or dependencies are failing. Prioritize core functionality over convenience features.

```python
async def process_chat_with_degradation(message: str, user_id: int) -> dict:
    """Process chat with graceful degradation"""

    # Check if voice input is available
    if message_type == "audio":
        if not degradation_manager.is_feature_available("voice_input"):
            return {
                "error": "Voice input temporarily unavailable",
                "suggestion": "Please send a text message instead"
            }

    # Check if AI generation is available
    if not degradation_manager.is_feature_available("chat"):
        # Fall back to template responses
        return {
            "answer": get_template_response(message),
            "degraded": True,
            "message": "AI features temporarily limited"
        }

    # Normal processing
    response = await chat_service.process_message(message, user_id)
    return response
```

## 📊 Error Classification

Classify errors by type (AI, Database, Network, Validation) and severity to enable appropriate handling and monitoring. Different error types require different retry strategies, logging levels, and user messages. Proper classification enables targeted alerts and faster debugging.

### Error Categories

```python
# app/core/exceptions.py

class ErrorCategory(Enum):
    """Error classification"""
    AI_ERROR = "ai"  # LLM, embedding, etc.
    DATABASE_ERROR = "database"  # SQL, connection, etc.
    NETWORK_ERROR = "network"  # API calls, timeouts
    VALIDATION_ERROR = "validation"  # Input validation
    AUTHENTICATION_ERROR = "auth"  # JWT, permissions
    BUSINESS_LOGIC_ERROR = "business"  # Application logic

class CategorizedError(Exception):
    """Base exception with category"""

    def __init__(
        self,
        message: str,
        category: ErrorCategory,
        details: dict = None
    ):
        super().__init__(message)
        self.message = message
        self.category = category
        self.details = details or {}
        self.timestamp = datetime.utcnow()

    def to_dict(self) -> dict:
        return {
            "error": self.message,
            "category": self.category.value,
            "details": self.details,
            "timestamp": self.timestamp.isoformat()
        }

# Specific error types
class LLMException(CategorizedError):
    def __init__(self, message: str, details: dict = None):
        super().__init__(message, ErrorCategory.AI_ERROR, details)

class DatabaseException(CategorizedError):
    def __init__(self, message: str, details: dict = None):
        super().__init__(message, ErrorCategory.DATABASE_ERROR, details)

class NetworkException(CategorizedError):
    def __init__(self, message: str, details: dict = None):
        super().__init__(message, ErrorCategory.NETWORK_ERROR, details)
```

## 💬 User-Safe Error Messages

Never expose internal error details, stack traces, or system information to users. Translate technical errors into user-friendly messages. Provide actionable guidance when possible. Include reference IDs for support purposes but hide implementation details.

### Error Message Sanitizer

```python
# app/core/error_messages.py

class ErrorMessageSanitizer:
    """Convert technical errors to user-friendly messages"""

    # Map technical errors to user messages
    ERROR_MAPPINGS = {
        # AI errors
        "openai.RateLimitError": "Our AI service is experiencing high demand. Please try again in a moment.",
        "openai.APIError": "We're experiencing technical difficulties. Please try again later.",
        "LLMException": "Unable to process your request at this time. Please try again.",

        # Database errors
        "sqlalchemy.exc.OperationalError": "Database temporarily unavailable. Please try again shortly.",
        "DatabaseException": "Unable to access your data. Please try again.",

        # Network errors
        "httpx.TimeoutException": "Request timed out. Please try again.",
        "NetworkException": "Network error occurred. Please check your connection.",

        # Validation errors
        "ValidationException": "Invalid input. Please check your input and try again.",
    }

    @staticmethod
    def sanitize(error: Exception) -> str:
        """Convert technical error to user-friendly message"""

        error_type = type(error).__name__
        error_message = str(error)

        # Check if we have a mapping
        if error_type in ErrorMessageSanitizer.ERROR_MAPPINGS:
            return ErrorMessageSanitizer.ERROR_MAPPINGS[error_type]

        # Check for specific error messages
        for pattern, message in ErrorMessageSanitizer.ERROR_MAPPINGS.items():
            if pattern in error_message:
                return message

        # Generic fallback
        return "An unexpected error occurred. Please try again or contact support."

    @staticmethod
    def create_error_response(error: Exception, include_technical: bool = False) -> dict:
        """Create standardized error response"""

        user_message = ErrorMessageSanitizer.sanitize(error)

        response = {
            "success": False,
            "error": {
                "message": user_message,
                "code": type(error).__name__
            }
        }

        # Include technical details only in development
        if include_technical and settings.DEBUG:
            response["error"]["technical"] = str(error)

        return response
```

### Error Response Handler

Centralize error response formatting to ensure consistent user-facing error messages across all endpoints. Include correlation IDs for tracking while sanitizing technical details. Log full error context server-side for debugging.

```python
@app.exception_handler(CategorizedError)
async def categorized_error_handler(request: Request, exc: CategorizedError):
    """Handle categorized errors"""

    # Log error with category
    logger.error(
        f"Error [{exc.category.value}]: {exc.message}",
        extra={"details": exc.details}
    )

    # Track error metrics
    error_metrics.increment(exc.category.value)

    # Create user-safe response
    response = ErrorMessageSanitizer.create_error_response(
        exc,
        include_technical=settings.DEBUG
    )

    return JSONResponse(
        status_code=500,
        content=response
    )
```

## 🚨 Common Mistakes to Avoid

❌ **No retry logic**

```python
# BAD
response = await llm.generate(prompt)  # Fails permanently on error
```

❌ **Exposing technical errors**

```python
# BAD
return {"error": str(e)}  # Shows stack traces to users!
```

❌ **No timeout**

```python
# BAD
await long_running_operation()  # Can hang forever
```

❌ **Single point of failure**

```python
# BAD
# Only one LLM provider, no fallback
```
