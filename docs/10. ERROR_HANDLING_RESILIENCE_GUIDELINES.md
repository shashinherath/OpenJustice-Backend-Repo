# Error Handling & Resilience Guidelines

## 📋 Purpose

Standardize **failure behavior** across the OpenJustice platform. Ensure consistent error responses, proper exception mapping, and user-safe error messages through the global error handler.

---

## 🎯 Core Principles

1. **Fail Safely** — Users never see stack traces or internal details
2. **Structured Responses** — All errors use `ErrorResponse` envelope
3. **Layered Exceptions** — Domain → Application → Presentation mapping
4. **Catch-All Handler** — Unhandled exceptions return generic 500 messages
5. **Service-Level Recovery** — Try/except with logging in every service

---

## 🏗️ Exception Architecture

The project follows Clean Architecture for exceptions: the domain layer defines business errors, the application layer adds HTTP metadata, and the presentation layer maps them to JSON responses.

```
Domain Exceptions                 Application Exceptions
┌─────────────────────┐          ┌──────────────────────┐
│ DomainError         │          │ AppError             │
│ ├─ AuthFailure      │          │   message: str       │
│ │  ├─ InvalidCreds  │          │   status_code: int   │
│ │  ├─ TokenExpired  │          │   error_code: str    │
│ │  └─ InvalidToken  │          │ ├─ AuthenticationErr │
│ └─ UserAlreadyExists│          └──────────────────────┘
└─────────────────────┘
                    ↓ Both caught by ↓
            Global Error Handler (setup_error_handlers)
                    ↓
            ErrorResponse JSON envelope
```

### Domain Exceptions

```python
# app/domain/exceptions/base.py
class DomainError(Exception):
    """Base class for domain-level errors."""

# app/domain/exceptions/auth.py
class AuthenticationFailure(DomainError):
    """Base for failures when establishing or validating identity."""

class InvalidCredentialsError(AuthenticationFailure):
    def __init__(self, message: str = "Invalid credentials"):
        self.message = message
        super().__init__(message)

class TokenExpiredError(AuthenticationFailure):
    def __init__(self, message: str = "Token has expired"):
        self.message = message
        super().__init__(message)

class InvalidTokenError(AuthenticationFailure):
    def __init__(self, message: str = "Could not validate credentials"):
        self.message = message
        super().__init__(message)

class UserAlreadyExistsError(DomainError):
    def __init__(self, message: str = "A user with this identifier already exists"):
        self.message = message
        super().__init__(message)
```

### Application Exceptions

Application errors carry HTTP metadata (`status_code` and `error_code`) that the global handler uses directly:

```python
# app/application/exceptions/app_errors.py
@dataclass
class AppError(Exception):
    """Base application error with HTTP metadata for API mapping."""
    message: str
    status_code: int
    error_code: str

    def __str__(self) -> str:
        return self.message

class AuthenticationError(AppError):
    def __init__(self, message: str = "Invalid credentials"):
        super().__init__(
            message=message,
            status_code=401,
            error_code="AUTHENTICATION_ERROR",
        )
```

## 🛡️ Global Error Handler

The `setup_error_handlers()` function registers FastAPI exception handlers that catch all exceptions and return standardized JSON responses. This is called in `main.py` at startup.

### Implementation

```python
# app/presentation/middleware/error_handler.py
from app.application.exceptions import AppError
from app.domain.exceptions import AuthenticationFailure, UserAlreadyExistsError
from app.presentation.schemas.response_schema import ErrorDetail, ErrorResponse


def setup_error_handlers(app: FastAPI) -> None:
    """Set up all global exception handlers for the FastAPI app."""

    @app.exception_handler(AppError)
    async def app_error_handler(request: Request, exc: AppError) -> JSONResponse:
        content = ErrorResponse(
            error=ErrorDetail(code=exc.error_code, message=exc.message)
        ).model_dump(mode="json")
        return JSONResponse(status_code=exc.status_code, content=content)

    @app.exception_handler(UserAlreadyExistsError)
    async def user_already_exists_handler(request, exc) -> JSONResponse:
        content = ErrorResponse(
            error=ErrorDetail(code="USER_ALREADY_EXISTS", message=exc.message)
        ).model_dump(mode="json")
        return JSONResponse(status_code=409, content=content)

    @app.exception_handler(AuthenticationFailure)
    async def authentication_failure_handler(request, exc) -> JSONResponse:
        content = ErrorResponse(
            error=ErrorDetail(code="AUTHENTICATION_ERROR", message=exc.message)
        ).model_dump(mode="json")
        return JSONResponse(status_code=401, content=content)

    @app.exception_handler(Exception)
    async def unhandled_exception_handler(request, exc) -> JSONResponse:
        content = ErrorResponse(
            error=ErrorDetail(
                code="INTERNAL_SERVER_ERROR",
                message="An unexpected error occurred. Please try again.",
            )
        ).model_dump(mode="json")
        return JSONResponse(status_code=500, content=content)
```

### Registration in main.py

```python
# app/main.py
from app.presentation.middleware.error_handler import setup_error_handlers

app = FastAPI(title=settings.APP_NAME, version=settings.APP_VERSION, ...)
setup_error_handlers(app)
```

## 📦 Standard Response Envelopes

All API responses use standardized Pydantic envelopes:

### Success Response

```python
# app/presentation/schemas/response_schema.py
class SuccessResponse(BaseModel, Generic[T]):
    success: bool = True
    data: T
    message: str = "Operation successful"
    timestamp: datetime = Field(default_factory=lambda: datetime.now(timezone.utc))
```

### Error Response

```python
class ErrorDetail(BaseModel):
    code: str       # e.g., "AUTHENTICATION_ERROR", "INTERNAL_SERVER_ERROR"
    message: str    # User-safe message

class ErrorResponse(BaseModel):
    success: bool = False
    error: ErrorDetail
    timestamp: datetime = Field(default_factory=lambda: datetime.now(timezone.utc))
```

### Example Responses

```json
// Success (200 OK)
{
  "success": true,
  "data": { "uuid": "...", "first_name": "John" },

    "message": "An unexpected error occurred. Please try again."
  },
  "timestamp": "2026-06-07T09:00:00Z"
}
```

## 🔄 Service-Level Error Handling

Each service wraps its operations in try/except blocks with logging. Failed operations update relevant statuses and re-raise or return gracefully.

### RAG Service Pattern

```python
# app/application/services/rag_service.py
async def process_and_store_document(self, document_id, storage_path, language):
    try:
        docs = loader.load()
        splits = text_splitter.split_documents(docs)
        vectors = await self.embeddings.aembed_documents(texts)
        await self.repository.save_chunks(db_chunks)
        await self.repository.update_status(document_id, "Processed")
    except Exception as e:
        await self.repository.update_status(document_id, "Failed")
        logger.error(f"Failed to process document {document_id}: {e}", exc_info=True)
```

## 📋 Checklist: Error Handling

✅ **Exception Hierarchy**

- [ ] `DomainError` as base for domain exceptions
- [ ] `AppError` with `status_code` and `error_code` for application exceptions
- [ ] Each exception type has a default message

✅ **Global Error Handler**

- [ ] `setup_error_handlers()` called in `main.py`
- [ ] `AppError` → mapped to its `status_code`
- [ ] `AuthenticationFailure` → 401
- [ ] `UserAlreadyExistsError` → 409
- [ ] Unhandled `Exception` → 500 with generic message

✅ **Response Format**

- [ ] All errors use `ErrorResponse` envelope
- [ ] All successes use `SuccessResponse` envelope
- [ ] Timestamps included in all responses

✅ **Service-Level**

- [ ] Try/except in every service method
- [ ] `exc_info=True` in all `logger.error()` calls
- [ ] Failed statuses updated (e.g., document → "Failed")
- [ ] No internal details exposed to users

## 🚨 Common Mistakes to Avoid

❌ **Exposing internal errors**

```python
# BAD — use the global error handler instead
return {"error": str(e)}
```

❌ **Missing exc_info in logs**

```python
# BAD — always include exc_info=True for full traceback
logger.error(f"Failed: {e}")
```

❌ **Not updating status on failure**

```python
# BAD — always update entity status when processing fails
try:
    process_document(doc_id)
except:
    pass  # Document stuck in "Pending" forever!
```

❌ **Raising generic exceptions**

```python
# BAD — use domain/application exceptions
raise Exception("Something went wrong")
```
