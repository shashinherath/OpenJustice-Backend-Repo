# Logging, Auditing & Traceability Guidelines

## 📋 Purpose

Enable **research evaluation** and **legal accountability** through database-backed telemetry. Track LLM decisions, RAG retrieval, user authentication events, and audio processing for analysis, debugging, and compliance.

---

## 🎯 Core Principles

1. **Database Telemetry** — Log AI decisions to PostgreSQL tables, not just stdout
2. **Standard Python Logging** — Use `logging.getLogger(__name__)` per module
3. **Protect Privacy** — Never log passwords, tokens, or PII in plaintext
4. **exc_info=True** — Always include full tracebacks in `logger.error()` calls
5. **Repository Pattern** — All telemetry writes go through interface → PostgreSQL repositories

---

## 🤖 LLM Decision Logging

Every LLM call is logged to the `llm_requests` and `llm_responses` tables via `ILLMLogRepository`. This records the query, context, model, token counts, latency, and status for research analysis and cost tracking.

### LLM Request Model

```python
# app/infrastructure/models/llm_request.py
class LLMRequest(Base):
    """Records every LLM API call for research and cost traceability."""
    __tablename__ = "llm_requests"

    id: Mapped[UUID]              # Primary key
    correlation_id: Mapped[UUID]  # Link related events
    user_id: Mapped[UUID]         # FK → users.id (indexed)
    query: Mapped[str]            # User's original query
    context: Mapped[str]          # RAG context sent to LLM
    model_name: Mapped[str]       # e.g., "gpt-4o-mini"
    prompt_version: Mapped[str]   # e.g., "v1"
    temperature: Mapped[float]    # e.g., 0.2
    prompt_tokens: Mapped[int]    # Estimated input tokens
    completion_tokens: Mapped[int]  # Estimated output tokens
    total_tokens: Mapped[int]     # Combined token count
    latency_ms: Mapped[int]       # Wall-clock time in milliseconds
    status: Mapped[str]           # "success" or "error"
    error_message: Mapped[str]    # Error details if status="error"
    created_at: Mapped[datetime]  # Auto-set by server_default=func.now()
```

### LLM Response Model

```python
# app/infrastructure/models/llm_response.py
class LLMResponse(Base):
    """Stores the text output from an LLM call."""
    __tablename__ = "llm_responses"

    id: Mapped[UUID]
    llm_request_id: Mapped[UUID]       # FK → llm_requests.id (CASCADE)
    response_text: Mapped[str]          # Full LLM response text
    confidence_level: Mapped[str]       # "High", "Medium", or "Low"
```

### How LLM Telemetry is Written

Inside `LLMService.generate_response()`, after every LLM call, telemetry is written to the database:

```python
# app/application/services/llm_service.py
async def generate_response(self, conversation_id, user_id, query, context, ...):
    # Build messages and call LLM
    start_time = time.perf_counter()
    response = await self.llm_client.generate_response(messages)
    latency_ms = int((time.perf_counter() - start_time) * 1000)

    # Log LLM Telemetry
    if self.llm_log_repository:
        try:
            prompt_text = "".join([m["content"] for m in messages])
            prompt_tokens = self._count_tokens(prompt_text)
            completion_tokens = self._count_tokens(response)
            total_tokens = prompt_tokens + completion_tokens

            req_id = await self.llm_log_repository.log_request(
                user_id=user_id,
                model_name=settings.OPENAI_MODEL,
                query=query,
                context=context,
                prompt_version="v1",
                temperature=settings.OPENAI_TEMPERATURE,
                prompt_tokens=prompt_tokens,
                completion_tokens=completion_tokens,
                total_tokens=total_tokens,
                latency_ms=latency_ms,
                status="success",
                error_message=None
            )
            await self.llm_log_repository.log_response(
                llm_request_id=req_id,
                response_text=response,
                confidence_level="High"
            )
        except Exception as e:
            logger.error(f"LLM telemetry logging failed: {e}", exc_info=True)
```

Token counting uses `tiktoken` with a fallback estimator:

```python
def _count_tokens(self, text: str) -> int:
    try:
        encoding = tiktoken.encoding_for_model(settings.OPENAI_MODEL)
        return len(encoding.encode(text))
    except Exception:
        return int(len(text.split()) * 1.3)
```

## 🔍 RAG Retrieval Logging

Every retrieval query is logged to the `retrieval_logs` table with linked `retrieved_documents`. This tracks which documents were retrieved, their similarity scores, and the query parameters.

### Retrieval Log Model

```python
# app/infrastructure/models/retrieval_log.py
class RetrievalLog(Base):
    """Logs each RAG retrieval query for traceability."""
    __tablename__ = "retrieval_logs"

    id: Mapped[UUID]
    correlation_id: Mapped[UUID]
    conversation_id: Mapped[UUID]
    query: Mapped[str]              # The search query
    language: Mapped[str]           # e.g., "English", "Sinhala"
    top_k: Mapped[int]             # How many chunks requested
    created_at: Mapped[datetime]

    # One-to-many with RetrievedDocument
    retrieved_documents: Mapped[list["RetrievedDocument"]] = relationship(...)
```

### Retrieved Document Model

```python
# app/infrastructure/models/retrieved_document.py
class RetrievedDocument(Base):
    """Links a retrieval log to the specific chunks retrieved."""
    __tablename__ = "retrieved_documents"

    id: Mapped[UUID]
    retrieval_log_id: Mapped[UUID]    # FK → retrieval_logs.id
    document_chunk_id: Mapped[UUID]   # FK → document_chunks.id
    similarity_score: Mapped[float]   # Cosine similarity
```

### How Retrieval Telemetry is Written

Inside `RetrievalService.retrieve()`:

```python
# app/application/services/retrieval_service.py
async def retrieve(self, query, language="English", threshold=0.7):
    top_k = self._determine_optimal_top_k(query)
    query_vector = await self.embeddings.aembed_query(query)
    chunks = await self.repository.search_similar_chunks(query_vector, limit=top_k, threshold=threshold)

    if self.log_repository:
        retrieved_data = [
            {"chunk_id": c.id, "similarity_score": getattr(c, "similarity", 0.0)}
            for c in chunks
        ]
        await self.log_repository.log_retrieval(
            conversation_id=None,
            query=query,
            language=language,
            top_k=top_k,
            retrieved_chunks=retrieved_data
        )

    return chunks, confidence
```

## 📝 Audit Trail

User actions (login, logout, registration, admin actions) are recorded in the `audit_logs` table via `IAuditLogRepository`. This provides a compliance trail for security auditing.

### Audit Log Model

```python
# app/infrastructure/models/audit_log.py
class AuditLog(Base):
    """Immutable audit trail for user actions and system events."""
    __tablename__ = "audit_logs"

    id: Mapped[UUID]
    user_id: Mapped[UUID]         # FK → users.id (indexed)
    action: Mapped[str]           # e.g., "LOGIN", "LOGOUT", "REGISTER"
    entity: Mapped[str]           # e.g., "user", "session"
    entity_id: Mapped[int]        # ID of the affected entity
    metadata_: Mapped[dict]       # JSONB — additional context
    created_at: Mapped[datetime]  # Auto-set by server_default=func.now()
```

### Repository Implementation

```python
# app/infrastructure/repositories/pg_audit_log_repository.py
class PgAuditLogRepository(IAuditLogRepository):
    """PostgreSQL implementation of Audit Logging."""

    async def log_action(
        self,
        user_id: UUID | None,
        action: str,
        entity: str | None = None,
        entity_id: int | None = None,
        metadata: dict | None = None
    ) -> None:
        audit_entry = AuditLog(
            user_id=user_id,
            action=action,
            entity=entity,
            entity_id=entity_id,
            metadata_=metadata
        )
        self.session.add(audit_entry)
        await self.session.commit()

    async def get_recent_activities(self, limit: int = 5) -> list:
        result = await self.session.execute(
            select(AuditLog).order_by(AuditLog.created_at.desc()).limit(limit)
        )
        return list(result.scalars().all())
```

### Where Audit Logging is Used

Audit logging is injected into `AuthService` via constructor and called on authentication events:

```python
# app/presentation/controllers/auth_controller.py
service = AuthService(
    repository=UserRepository(db),
    password_hasher=BcryptPasswordHasher(),
    token_issuer=jwt_handler,
    user_session_repo=PgUserSessionRepository(db),
    audit_log_repo=PgAuditLogRepository(db),     # ← Audit logging injected
)
```

Events logged include: `LOGIN`, `LOGOUT`, `REGISTER`, and admin actions.

## 📊 Telemetry Tables Summary

| Table | Purpose | Written By | Key Fields |
|---|---|---|---|
| `llm_requests` | LLM call traceability | `LLMService` via `PgLLMLogRepository` | model, tokens, latency, status |
| `llm_responses` | LLM response text | `LLMService` via `PgLLMLogRepository` | response_text, confidence |
| `retrieval_logs` | RAG query traceability | `RetrievalService` via `PgRetrievalLogRepository` | query, language, top_k |
| `retrieved_documents` | Retrieved chunk links | `RetrievalService` via `PgRetrievalLogRepository` | chunk_id, similarity_score |
| `audit_logs` | User action trail | `AuthService` via `PgAuditLogRepository` | action, entity, metadata |
| `audio_requests` | STT/TTS telemetry | `WhatsAppService` via `PgAudioLogRepository` | audio_type, duration, provider |

## 🔧 Standard Python Logging

Every module uses Python's built-in `logging` with `getLogger(__name__)`. There is no custom logging framework — the project relies on standard Python logging that FastAPI/uvicorn captures.

### Module-Level Logger Pattern

```python
# Every service follows this pattern
import logging
logger = logging.getLogger(__name__)

class SomeService:
    async def do_something(self):
        logger.info(f"Starting operation")
        try:
            result = await self.some_call()
            logger.info(f"Operation completed successfully")
        except Exception as e:
            logger.error(f"Operation failed: {e}", exc_info=True)
            raise
```

### Logging Levels Used

| Level | Usage in Codebase |
|---|---|
| `DEBUG` | Not commonly used in services |
| `INFO` | Operation starts, completions, cache hits, detections |
| `WARNING` | Prompt injection detected, unknown users, rate limit |
| `ERROR` | Service failures with `exc_info=True` for full traceback |

---

## 🚫 What NOT to Log

| Data Type | Rule |
|---|---|
| Passwords | Never log — not even hashed |
| JWT tokens | Never log full tokens |
| API keys | Never log — use settings references |
| Full email/phone | Use user_id instead |
| Full request bodies | Log length/hash, not content |
| Stack traces (user-facing) | Use `ErrorResponse` envelope, log internally only |

## 📋 Checklist: Logging & Traceability

✅ **LLM Telemetry**

- [ ] `PgLLMLogRepository` injected into `LLMService`
- [ ] `log_request()` called after every LLM call
- [ ] `log_response()` called with response text
- [ ] Token counts estimated via `tiktoken`
- [ ] Latency measured with `time.perf_counter()`

✅ **RAG Telemetry**

- [ ] `PgRetrievalLogRepository` injected into `RetrievalService`
- [ ] `log_retrieval()` called with query, language, top_k
- [ ] Retrieved chunks linked via `RetrievedDocument`

✅ **Audit Trail**

- [ ] `PgAuditLogRepository` injected into `AuthService`
- [ ] LOGIN, LOGOUT, REGISTER events logged
- [ ] `metadata_` JSONB field used for additional context

✅ **Standard Logging**

- [ ] `logger = logging.getLogger(__name__)` in every module
- [ ] `exc_info=True` in all `logger.error()` calls
- [ ] No passwords, tokens, or PII in log messages

## 🚨 Common Mistakes to Avoid

❌ **Missing exc_info**

```python
# BAD — no traceback in error log
logger.error(f"Failed: {e}")

# GOOD
logger.error(f"Failed: {e}", exc_info=True)
```

❌ **Logging sensitive data**

```python
# BAD
logger.info(f"User password: {password}")
logger.info(f"Token: {jwt_token}")
```

❌ **Skipping telemetry logging**

```python
# BAD — LLM call without telemetry
response = await llm_client.generate_response(messages)
return response  # No log_request/log_response!
```

❌ **Silent exception swallowing**

```python
# BAD — errors disappear silently
except Exception:
    pass
```
