# Messaging & WhatsApp Integration Guidelines

## 📋 Purpose

Maintain reliable **WhatsApp messaging** via Twilio webhooks and **HTTP streaming** for web chat. Ensure secure webhook handling, background processing, and proper message flow between channels.

---

## 🎯 Core Principles

1. **Background Processing** — WhatsApp handlers run via `BackgroundTasks` to return 200 OK immediately
2. **Channel Separation** — Web chat uses HTTP streaming, WhatsApp uses Twilio webhooks
3. **Auto-User Provisioning** — WhatsApp users are created dynamically from phone numbers
4. **Voice Round-Trip** — STT → RAG → LLM → TTS for WhatsApp voice notes
5. **Twilio Compliance** — Return TwiML XML response within 15 seconds

---

## 🏗️ Architecture Overview

The platform has two messaging channels, each with a distinct communication pattern:

```
Web Chat Channel:                        WhatsApp Channel:
  Browser → POST /chats/{id}/complete     Twilio → POST /whatsapp/webhook
         → StreamingResponse (text/plain)         → BackgroundTasks (async)
                                                  → TwilioWhatsAppClient.send_message()
```

There are **no WebSockets** in the current implementation. Web chat uses HTTP streaming via FastAPI's `StreamingResponse`, and WhatsApp uses Twilio webhooks with background task processing.

## 📱 WhatsApp Webhook (Twilio)

The WhatsApp controller receives incoming messages from Twilio as form-encoded POST data. The handler delegates to `BackgroundTasks` immediately to return a 200 OK to Twilio within its 15-second timeout.

### Controller

```python
# app/presentation/controllers/whatsapp_controller.py
router = APIRouter(prefix="/whatsapp", tags=["WhatsApp"])


@router.post("/webhook")
async def twilio_webhook(
    background_tasks: BackgroundTasks,
    From: str = Form(...),
    To: str = Form(...),
    Body: str = Form(""),
    MediaUrl0: str = Form(None),
    whatsapp_service: WhatsAppService = Depends(get_whatsapp_service)
):
    """Webhook endpoint to receive incoming WhatsApp messages from Twilio."""
    logger.info(f"Incoming webhook from Twilio: From={From}, Body={Body}")

    # Run the handler in the background to ensure we return 200 OK immediately.
    # Twilio expects a response within 15 seconds.
    background_tasks.add_task(
        whatsapp_service.handle_incoming_message,
        from_number=From,
        body=Body,
        media_url=MediaUrl0
    )

    # Return empty TwiML response
    return Response(content="<Response></Response>", media_type="application/xml")
```

### Key Design Decisions

- **Form parameters**: Twilio sends `From`, `To`, `Body`, and `MediaUrl0` as form fields, not JSON
- **Background processing**: The entire `handle_incoming_message` flow runs in a `BackgroundTasks` callback so Twilio gets its 200 OK immediately
- **TwiML response**: An empty `<Response></Response>` XML tells Twilio "received OK, no immediate reply" — the reply is sent later via the Twilio API
- **Public path**: `/api/whatsapp/webhook` is listed in `PUBLIC_PATHS` in `AuthMiddleware` (no JWT required)

## 🔄 WhatsApp Message Flow

The `WhatsAppService` orchestrates the full message lifecycle: user lookup, conversation management, RAG retrieval, LLM generation, and optional TTS response.

### Implementation

```python
# app/application/services/whatsapp_service.py
class WhatsAppService:
    """Service to handle WhatsApp messaging logic."""

    def __init__(self, whatsapp_client: IWhatsAppClient, llm_service: LLMService,
                 db: AsyncSession, audio_log_repository: IAudioLogRepository = None):
        self.whatsapp_client = whatsapp_client
        self.llm_service = llm_service
        self.db = db
        self.audio_log_repository = audio_log_repository
        self.retrieval_service = RetrievalService(DocumentRepository(db), ...)

    async def handle_incoming_message(self, from_number: str, body: str = None,
                                       media_url: str = None) -> None:
        """Process incoming WhatsApp message or voice note."""

        # 1. Lookup or create User from phone number
        phone = from_number.replace('whatsapp:', '').strip()
        user = await self._get_or_create_user(phone)

        # 2. Handle voice note (STT)
        if media_url:
            audio_path = await TempFileManager.download_twilio_audio(media_url)
            stt_service = SpeechToTextService()
            body = await stt_service.transcribe_audio(audio_path)

        # 3. Get or create WhatsApp conversation
        conv = await self._get_or_create_conversation(user.id, channel="whatsapp")

        # 4. Retrieve context via RAG
        chunks, confidence = await self.retrieval_service.retrieve(query=body)
        context = "\n\n---\n\n".join([f"REFERENCE TEXT:\n{c.content}" for c in chunks])

        # 5. Generate LLM response
        reply = await self.llm_service.generate_response(
            conversation_id=conv.id, user_id=user.id, query=body, context=context
        )

        # 6. If voice input, synthesize TTS audio and send via Twilio
        if media_url:
            tts_service = TextToSpeechService()
            out_audio_path = await tts_service.synthesize_speech(reply)
            filename = out_audio_path.split("/")[-1].split("\\")[-1]
            public_url = f"{settings.PUBLIC_BASE_URL}/temp/{filename}"
            await self.whatsapp_client.send_message(to=from_number, media_url=public_url)
            return

        # 7. Otherwise, send text reply
        await self.whatsapp_client.send_message(to=from_number, body=reply)
```

### Auto-User Provisioning

WhatsApp users are created automatically when they first message the system:

```python

user = User(phone_number=phone, hashed_password="whatsapp_auto_user_system", role="user")
self.db.add(user)
await self.db.commit()
```

## 💬 Web Chat Streaming

Web chat uses HTTP streaming rather than WebSockets. The `POST /chats/{id}/messages/complete` endpoint returns a `StreamingResponse` that streams LLM tokens as plain text:

```python
# app/presentation/controllers/chat_controller.py
@router.post("/{conversation_id}/messages/complete")
async def complete_message(conversation_id: UUID, data: MessageCompleteRequest, ...):
    """Generate AI reply, streaming the response."""

    # Retrieve context
    chunks, confidence = await retrieval_service.retrieve(query=data.query)
    context = data.context
    if chunks:
        context_add = "\n\n---\n\n".join([f"REFERENCE TEXT:\n{c.content}" for c in chunks])
        context = f"{context}\n\n{context_add}"

    async def event_generator():
        async for chunk in llm_service.stream_response(conversation_id, user_id, data.query, context):
            yield chunk

    return StreamingResponse(event_generator(), media_type="text/plain")
```

## 🔧 Twilio Configuration

### Environment Variables

```python
# app/config.py
class Settings(BaseSettings):
    TWILIO_ACCOUNT_SID: Optional[str] = None
    TWILIO_AUTH_TOKEN: Optional[str] = None
    TWILIO_WHATSAPP_NUMBER: Optional[str] = None
    PUBLIC_BASE_URL: str = "http://localhost:8000"
```

### Local Development with Twilio Sandbox

1. Set Twilio credentials in `.env`:
```env
TWILIO_ACCOUNT_SID=your_account_sid
TWILIO_AUTH_TOKEN=your_auth_token
TWILIO_WHATSAPP_NUMBER=whatsapp:+14155238886
```

2. Start the FastAPI backend:
```bash
uv run uvicorn app.main:app --reload
```

3. Expose your server via ngrok:
```bash
ngrok http 8000
```

4. In the [Twilio Console Sandbox](https://console.twilio.com/us1/develop/sms/settings/whatsapp-sandbox), set the webhook URL to `https://<NGROK_URL>/api/whatsapp/webhook`.

5. Send a message to the sandbox number and verify your local service receives it.

## 🔊 Voice Note Flow (WhatsApp)

When a user sends a voice note, the system performs a full audio round-trip:

```
Twilio MediaUrl0 → TempFileManager.download_twilio_audio()
    → SpeechToTextService.transcribe_audio() (Whisper)
    → RetrievalService.retrieve() (RAG)
    → LLMService.generate_response()
    → TextToSpeechService.synthesize_speech() (TTS)
    → Serve via /temp/ static mount
    → TwilioWhatsAppClient.send_message(media_url=...)
```

Audio telemetry is logged via `IAudioLogRepository` for both STT and TTS steps.

## 📋 Checklist: Messaging Integration

✅ **WhatsApp Webhook**

- [ ] `POST /api/whatsapp/webhook` endpoint registered
- [ ] Path listed in `PUBLIC_PATHS` (no JWT required)
- [ ] Processing runs in `BackgroundTasks` (non-blocking)
- [ ] Returns `<Response></Response>` TwiML immediately

✅ **Web Chat**

- [ ] `POST /chats/{id}/messages/complete` returns `StreamingResponse`
- [ ] `POST /chats/{id}/messages/voice` handles voice uploads
- [ ] JWT authentication required (via `AuthMiddleware`)

✅ **Voice Notes**

- [ ] Twilio audio downloaded via `TempFileManager.download_twilio_audio()`
- [ ] STT via `SpeechToTextService` (Whisper)
- [ ] TTS via `TextToSpeechService` (OpenAI TTS)
- [ ] Audio served via `/temp/` static mount with `PUBLIC_BASE_URL`

## 🚨 Common Mistakes to Avoid

❌ **Blocking the webhook**

```python
# BAD — Twilio times out after 15 seconds
@router.post("/webhook")
async def webhook(Body: str):
    reply = await slow_llm_call(Body)  # Takes 10+ seconds!
    return {"reply": reply}
```

❌ **Missing TwiML response**

```python
# BAD — Twilio expects XML, not JSON
return {"status": "ok"}
```

❌ **Forgetting PUBLIC_BASE_URL**

```python
# BAD — Twilio can't access localhost URLs
media_url = f"http://localhost:8000/temp/{filename}"
```
