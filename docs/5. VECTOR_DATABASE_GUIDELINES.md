# Vector Database & Embedding Guidelines

## 📋 Purpose

Maintain **consistency** and **reproducibility** in vector search operations using **pgvector**. Ensure embedding lifecycle management, immutability, and proper indexing strategies.

---

## 🎯 Core Principles

1. **Immutability** — Embeddings never change after creation (enforced by SQLAlchemy validator)
2. **Versioning** — Track embedding model + chunking version on every record
3. **Single Distance Metric** — Cosine similarity via pgvector `<=>` operator
4. **Schema Consistency** — UUID primary keys, `Mapped[]` column syntax, 3072-dimension vectors
5. **Cleanup Strategy** — `VectorCleanupService` handles orphaned and archived chunks

---

## 🗄️ DocumentChunk Schema

The `DocumentChunk` model stores text content alongside its pgvector embedding. It uses UUID primary keys, modern SQLAlchemy `Mapped[]` syntax, and includes version tracking columns.

### ORM Model

```python
# app/infrastructure/models/document_chunk.py
from pgvector.sqlalchemy import Vector
from sqlalchemy.orm import Mapped, mapped_column, relationship, validates

class DocumentChunk(Base):
    """A chunk of a document with its vector embedding for RAG retrieval."""
    __tablename__ = "document_chunks"

    __table_args__ = (
        CheckConstraint("chunk_index >= 0", name="valid_chunk_index"),
        CheckConstraint("chunk_size > 0", name="valid_chunk_size"),
        Index("idx_doc_chunks_doc_id", "document_id"),
        Index("idx_doc_chunks_lang", "language"),
        Index("idx_doc_chunks_embedding_model", "embedding_model"),
    )

    id: Mapped[uuid.UUID] = mapped_column(PGUUID(as_uuid=True), primary_key=True, default=uuid.uuid4)
    document_id: Mapped[uuid.UUID] = mapped_column(
        PGUUID(as_uuid=True), ForeignKey("documents.id", ondelete="CASCADE"), index=True
    )
    content: Mapped[str] = mapped_column(Text, nullable=False)
    language: Mapped[str] = mapped_column(String(20), nullable=False, default="English")

    # 3072 dimensions for text-embedding-3-large
    embedding: Mapped[list] = mapped_column(Vector(3072), nullable=False)

    # JSONB metadata (LangChain document metadata: page numbers, source path)
    metadata_: Mapped[Optional[dict]] = mapped_column("metadata", JSONB, nullable=True, default=dict)

    # Chunk position tracking
    chunk_index: Mapped[int] = mapped_column(Integer, nullable=False)
    chunk_total: Mapped[int] = mapped_column(Integer, nullable=False)
    chunk_size: Mapped[int] = mapped_column(Integer, nullable=False)

    # Version tracking (CRITICAL for reproducibility)
    embedding_model: Mapped[str] = mapped_column(String(100), nullable=False)
    embedding_version: Mapped[str] = mapped_column(String(20), nullable=False)
    chunking_version: Mapped[str] = mapped_column(String(20), nullable=False, default="v1")

    # Timestamps
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())
    updated_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now(), onupdate=func.now())

    # Relationships
    document: Mapped["Document"] = relationship("Document", back_populates="chunks")
    retrieved_in: Mapped[list["RetrievedDocument"]] = relationship(
        "RetrievedDocument", back_populates="document_chunk", cascade="all, delete-orphan"
    )
```

### Key Schema Details

| Column | Type | Purpose |
|---|---|---|
| `id` | UUID | Primary key (not integer) |
| `document_id` | UUID FK | References `documents.id`, cascades on delete |
| `embedding` | `Vector(3072)` | pgvector column for `text-embedding-3-large` |
| `metadata_` | JSONB | LangChain metadata (page numbers, source path) |
| `embedding_model` | String | Which model generated the embedding |
| `embedding_version` | String | Model version (e.g., `"v3"`) |
| `chunking_version` | String | Chunking algorithm version (e.g., `"v1"`) |

## 📏 Distance Metrics (Cosine Only)

The project exclusively uses cosine distance for all vector similarity operations. pgvector's `<=>` operator computes cosine distance (1 − cosine_similarity). Lower distance = more similar.

### Why Cosine?

- **Normalized** — Magnitude-independent comparison
- **Semantic** — Best for text embeddings
- **Consistent** — OpenAI embeddings are pre-normalized
- **Standard** — Industry default for RAG applications

### SQLAlchemy Query (Actual Implementation)

The `DocumentRepository` uses pgvector's native SQLAlchemy integration rather than raw SQL:

```python
# app/infrastructure/repositories/document_repository.py
async def search_similar_chunks(
    self, query_embedding: list[float], limit: int = 5, threshold: float = 0.7
) -> List[DocumentChunk]:
    """Uses pgvector's cosine_distance to return the closest chunks.
    A threshold of 0.7 means cosine distance must be < 0.3."""

    max_distance = 1.0 - threshold

    stmt = (
        select(DocumentChunk)
        .where(DocumentChunk.embedding.cosine_distance(query_embedding) < max_distance)
        .order_by(DocumentChunk.embedding.cosine_distance(query_embedding))
        .limit(limit)
    )
    result = await self.session.execute(stmt)
    return list(result.scalars().all())
```

The `cosine_distance()` method on the `Vector` column compiles to pgvector's `<=>` operator:

```sql
-- Generated SQL
SELECT * FROM document_chunks
WHERE (embedding <=> $1) < 0.3      -- threshold 0.7 → max_distance 0.3
ORDER BY embedding <=> $1
LIMIT 5
```

### Distance Operators Reference

```python
# pgvector operators (PostgreSQL)
# <=>  : Cosine distance     (USE THIS — project standard)
# <->  : L2 distance         (DO NOT USE)
# <#>  : Inner product        (DO NOT USE)
```

## 🔒 Embedding Immutability

Embeddings are immutable after creation. This is enforced at the ORM level with a SQLAlchemy `@validates` decorator that raises `ValueError` if an existing embedding is modified:

```python
# app/infrastructure/models/document_chunk.py
@validates('embedding')
def validate_embedding_immutable(self, key, value):
    """Prevent embedding modification after creation to ensure reproducibility."""
    if self.id is not None and getattr(self, 'embedding', None) is not None:
        raise ValueError(
            "Embeddings are immutable. Create a new chunk instead of updating."
        )
    return value
```

### Updating Documents

When document content changes, delete old chunks and create new ones. Never update the embedding column directly:

```python
# ❌ WRONG: Update existing embedding
chunk.embedding = new_embedding  # Raises ValueError!

# ✅ CORRECT: Delete old chunks, create new ones
await repository.delete_document_chunks(document_id)
await rag_service.process_and_store_document(document_id, storage_path)
```

## 📦 Embedding Model Configuration

The embedding model is configured in `app/config.py` and used consistently across `RAGService` and `RetrievalService`:

```python
# app/config.py
class Settings(BaseSettings):
    OPENAI_EMBEDDING_MODEL: str = "text-embedding-3-large"  # 3072 dimensions
```

Both services initialize `OpenAIEmbeddings` from LangChain with the same model:

```python
# Used in both RAGService and RetrievalService
self.embeddings = OpenAIEmbeddings(
    model=settings.OPENAI_EMBEDDING_MODEL,
    api_key=settings.OPENAI_API_KEY
)

# For document ingestion (batch):
vectors = await self.embeddings.aembed_documents(texts)

# For query embedding (single):
query_vector = await self.embeddings.aembed_query(query)
```

### Version Tracking on Every Chunk

Every `DocumentChunk` records which model generated its embedding:

```python
chunk = DocumentChunk(
    embedding=vector,
    embedding_model=settings.OPENAI_EMBEDDING_MODEL,  # "text-embedding-3-large"
    embedding_version="v3",                            # OpenAI model version
    chunking_version="v1",                             # Chunking algorithm version
)
```

This enables safe model upgrades — you can identify which chunks were generated by which model and re-index selectively.

## 🧹 Vector Cleanup Service

The `VectorCleanupService` identifies and removes obsolete vector data. It handles two cleanup scenarios:

### Orphaned Chunks

Chunks whose parent document has been deleted (the `ON DELETE CASCADE` on the FK handles most cases, but this catches edge cases):

```python
# app/application/services/vector_cleanup_service.py
class VectorCleanupService:
    """Clean up orphaned and archived pgvector chunks."""

    def __init__(self, db: AsyncSession):
        self.db = db

    async def find_orphaned_chunks(self) -> List[str]:
        """Find chunks referencing deleted documents."""
        sql = text("""
            SELECT dc.id
            FROM document_chunks dc
            LEFT JOIN documents d ON dc.document_id = d.id
            WHERE d.id IS NULL
        """)
        result = await self.db.execute(sql)
        return [str(row.id) for row in result.fetchall()]
```

### Archived Chunks

Chunks marked as archived in their JSONB metadata, older than 30 days:

```python
    async def find_archived_chunks(self, older_than_days: int = 30) -> List[str]:
        """Find archived chunks older than threshold."""
        sql = text("""
            SELECT id
            FROM document_chunks
            WHERE metadata->>'archived' = 'true'
            AND (metadata->>'archived_at')::timestamp < NOW() - :days * INTERVAL '1 day'
        """)
        result = await self.db.execute(sql, {"days": older_than_days})
        return [str(row.id) for row in result.fetchall()]
```

### Batch Deletion

```python
    async def delete_chunks_batch(self, chunk_ids: List[str], batch_size: int = 100):
        """Delete chunks in batches safely."""
        for i in range(0, len(chunk_ids), batch_size):
            batch = chunk_ids[i:i+batch_size]
            sql = text("DELETE FROM document_chunks WHERE id::text = ANY(:ids)")
            await self.db.execute(sql, {"ids": batch})
            await self.db.commit()

    async def cleanup_old_vectors(self):
        """Execute full cleanup process."""
        orphaned = await self.find_orphaned_chunks()
        archived = await self.find_archived_chunks(older_than_days=30)
        to_delete = list(set(orphaned + archived))

        if to_delete:
            logger.warning(f"Deleting {len(to_delete)} obsolete pgvector chunks...")
            await self.delete_chunks_batch(to_delete)
```

## 🔍 Semantic Cache

In addition to document chunks, the project stores a separate pgvector table for semantic caching of LLM responses:

```python
# app/infrastructure/models/semantic_cache.py
class SemanticCache(Base):
    """Semantic cache mapping queries to generated responses.
    Uses pgvector for semantic search (95% similarity match)."""

    __tablename__ = "semantic_caches"

    id = Column(UUID(as_uuid=True), primary_key=True, default=uuid.uuid4)
    query_text = Column(String, nullable=False)
    query_embedding = Column(Vector(3072), nullable=False)  # text-embedding-3-large
    response_text = Column(String, nullable=False)
    created_at = Column(DateTime, default=datetime.utcnow, nullable=False)
```

The cache uses the same `text-embedding-3-large` model (3072 dimensions) as document chunks. Matching threshold is controlled by `settings.CACHE_SIMILARITY_THRESHOLD` (default: 0.95).

## 📋 Checklist: Vector Operations

✅ **Schema**

- [ ] pgvector extension enabled (`CREATE EXTENSION IF NOT EXISTS vector`)
- [ ] `Vector(3072)` column matches `text-embedding-3-large` dimensions
- [ ] UUID primary keys (not integers)
- [ ] Version fields included (`embedding_model`, `embedding_version`, `chunking_version`)
- [ ] JSONB `metadata_` column for flexible LangChain metadata
- [ ] Indexes on `document_id`, `language`, and `embedding_model`

✅ **Distance Metric**

- [ ] Using cosine distance via `DocumentChunk.embedding.cosine_distance()`
- [ ] NOT using raw SQL `<=>` operator (use ORM method instead)
- [ ] Threshold applied (default: 0.7 similarity → 0.3 max distance)

✅ **Immutability**

- [ ] `@validates('embedding')` prevents modification after creation
- [ ] Document updates delete old chunks and create new ones
- [ ] No direct `UPDATE` on embedding column

✅ **Versioning**

- [ ] `embedding_model` stored on every chunk
- [ ] `embedding_version` tracked
- [ ] `chunking_version` recorded
- [ ] Model name comes from `settings.OPENAI_EMBEDDING_MODEL`

✅ **Cleanup**

- [ ] `VectorCleanupService` detects orphaned chunks
- [ ] Archived chunks cleaned after 30 days
- [ ] Batch deletion for performance (100 per batch)
- [ ] Cleanup logging enabled

## 🚨 Common Mistakes to Avoid

❌ **Wrong distance metric**

```sql
-- BAD — always use <=> (cosine distance)
ORDER BY embedding <-> query_vec  -- This is L2 distance!
```

❌ **Updating embeddings**

```python
# BAD — raises ValueError due to @validates
chunk.embedding = new_embedding
```

❌ **Missing version tracking**

```python
# BAD — always include model and version metadata
chunk = DocumentChunk(content=text, embedding=vec)  # No version!
```

❌ **Wrong dimension count**

```python
# BAD — must match OPENAI_EMBEDDING_MODEL dimensions
embedding = Column(Vector(1536))  # Wrong! text-embedding-3-large is 3072
```

❌ **Raw SQL for vector search**

```python
# BAD — use ORM cosine_distance() method
sql = text("SELECT * FROM document_chunks ORDER BY embedding <=> :vec")
```
