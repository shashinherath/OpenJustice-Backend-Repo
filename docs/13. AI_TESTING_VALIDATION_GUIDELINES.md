# 13️⃣ AI Testing & Validation Guidelines

## 📋 Purpose

Standard software testing (Unit/Integration) is insufficient for stochastic AI systems. The purpose of these guidelines is to extend testing into the AI domain. This ensures that changes to our prompts, vector embeddings, and LLM configurations do not cause regressions in retrieval accuracy or conversational quality.

---

## 🎯 Core Principles

1. **Test the Pipeline, Not Just Code** - Ensure the RAG loop returns semantically accurate answers.
2. **Mock When Possible** - Avoid spending API credits on simple logic tests.
3. **Catch Drift Early** - Prevent regressions when OpenAI pushes minor model updates behind the scenes.
4. **Multilingual Equity** - Ensure translations and Indic language retrievals do not degrade over time.

---

## 🎭 Mocking LLM Responses

Running real OpenAI calls during CI/CD pipelines is slow, expensive, and flaky. 

### Standard Unit Testing
For logic tests (e.g., "does the chat service save the message to the database?"), **always mock the LLM Client**.

```python
# tests/mocks/mock_llm_client.py
from app.domain.interfaces.llm_client import ILLMClient

class MockLLMClient(ILLMClient):
    """Mocks the OpenAI API to prevent burning credits during CI/CD."""
    
    async def generate_response(self, messages: list[dict]) -> str:
        return "This is a deterministic mocked response."
        
    async def generate_stream(self, messages: list[dict]):
        yield "This "
        yield "is a "
        yield "streamed mock."
```

In your `pytest` fixtures, override the dependency injection to use the `MockLLMClient` instead of the `OpenAIClient`.

## 📝 Prompt Tests

Prompts are essentially code. Small wording changes can drastically alter output format. 

### Output Format Enforcement
Test that the LLM respects JSON formatting or structural constraints requested by the prompt.

```python
# tests/ai/test_prompts.py
import pytest
from app.application.services.llm_service import MultilingualPromptBuilder

@pytest.mark.ai_integration
async def test_citation_formatting_prompt(live_llm_client):
    """Ensure the prompt successfully forces the LLM to output [Source: X] citations."""
    
    prompt = MultilingualPromptBuilder.build_system_prompt(
        language="English", 
        context="According to the Penal Code Section 300, murder is illegal."
    )
    
    messages = [
        {"role": "system", "content": prompt},
        {"role": "user", "content": "What does section 300 say?"}
    ]
    
    response = await live_llm_client.generate_response(messages)
    
    assert "[Source:" in response, "Prompt failed to enforce citation formatting!"
```

## 🔍 Retrieval Accuracy Tests

Before worrying about the LLM's answer, we must verify that the Vector DB is returning the correct documents.

### Hit Rate and MRR (Mean Reciprocal Rank)
Create a static test dataset of common queries and their expected `document_id`s or `chunk_id`s.

```python
# tests/ai/test_retrieval.py

EVAL_QUERIES = [
    {"query": "Penalty for theft", "expected_doc_id": "penal_code_367"},
    {"query": "Divorce proceedings", "expected_doc_id": "marriage_act_19"},
]

@pytest.mark.ai_integration
async def test_retrieval_hit_rate(retrieval_service):
    """Ensure top_k=5 retrieval fetches the ground-truth document."""
    
    hits = 0
    for test in EVAL_QUERIES:
        chunks, _ = await retrieval_service.retrieve(test["query"], top_k=5)
        retrieved_doc_ids = [c.document_id for c in chunks]
        
        if test["expected_doc_id"] in retrieved_doc_ids:
            hits += 1
            
    hit_rate = hits / len(EVAL_QUERIES)
    assert hit_rate >= 0.90, f"Retrieval accuracy degraded! Hit rate: {hit_rate}"
```

## 🌍 Multilingual Consistency Tests

Changes to tokenization, embeddings, or prompts can disproportionately impact Sinhala and Tamil capabilities.

### Semantic Parity Testing
When asking the exact same legal question in three different languages, the retrieved context should be semantically identical.

```python
# tests/ai/test_multilingual.py

@pytest.mark.ai_integration
async def test_cross_lingual_retrieval_parity(retrieval_service):
    queries = {
        "English": "What are the rules for adopting a child?",
        "Sinhala": "ළමයෙකු දරුකමට හදා ගැනීමේ නීති මොනවාද?",
        "Tamil": "ஒரு குழந்தையை தத்தெடுப்பதற்கான விதிகள் என்ன?"
    }
    
    results = {}
    for lang, query in queries.items():
        chunks, _ = await retrieval_service.retrieve(query, top_k=3)
        results[lang] = {c.document_id for c in chunks}
        
    # Ensure that all languages retrieved at least one common core document
    common_docs = results["English"] & results["Sinhala"] & results["Tamil"]
    assert len(common_docs) > 0, "Multilingual retrieval has diverged!"
```

## 🔄 Regression Tests for RAG

When migrating from `text-embedding-3-small` to `text-embedding-3-large`, or when changing `CHUNK_SIZE`, we must guarantee we did not break existing system behavior.

### Baseline Snapshots
1. Run a suite of 50 standard queries against the production pipeline.
2. Save the LLM outputs to a baseline JSON file.
3. When testing a PR that alters the RAG architecture, re-run the 50 queries.
4. Use a cheap LLM (`gpt-4o-mini`) as a "Judge" to verify that the new answers are semantically equivalent or superior to the baseline snapshot.

```python
# tests/ai/test_rag_regression.py
async def test_no_regression_against_baseline(rag_service, llm_judge):
    baseline = load_baseline_snapshot("v1_0_baseline.json")
    
    for case in baseline:
        new_answer = await rag_service.answer(case["question"])
        
        # LLM as a Judge
        is_equivalent = await llm_judge.check_semantic_equivalence(
            reference=case["answer"],
            prediction=new_answer
        )
        assert is_equivalent, f"Regression detected on query: {case['question']}"
```

## 🗃️ Evaluation Test Datasets

To run the above tests consistently, we must maintain static evaluation datasets in the repository.

* **Location**: Store datasets in `tests/data/eval_datasets/`
* **Format**: Standardized JSON Lines (`.jsonl`) to allow easy streaming into testing frameworks.

### Anatomy of a Test Dataset
```json
// tests/data/eval_datasets/retrieval_ground_truth.jsonl
{"query_id": "q1", "query": "Land dispute resolution time", "target_chunks": ["chunk_land_42"], "lang": "English"}
{"query_id": "q2", "query": "ඉඩම් ආරවුල් විසඳීමේ කාලය", "target_chunks": ["chunk_land_42"], "lang": "Sinhala"}
```

### Dataset Curation
* Curate these datasets manually. When the system fails a user query in production, anonymize it, find the correct document chunk that *should* have been returned, and add it to the test dataset. This ensures we practice **Test-Driven AI Development**.
