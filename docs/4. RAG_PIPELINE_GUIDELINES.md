# RAG Pipeline Coding Guidelines

## 📋 Purpose

Enforce strict **separation of retrieval and generation** logic for the OpenJustice RAG (Retrieval-Augmented Generation) system. Ensure accuracy, reproducibility, and maintainability.

---

## 🎯 Core Principles

1. **Separation of Concerns** — `RAGService` (ingestion) ≠ `RetrievalService` (search) ≠ `LLMService` (generation)
2. **Deterministic Retrieval** — Same query embedding → same document chunks
3. **Citation Traceability** — System prompts enforce `[Source: Act Name, Section Number]` citations
4. **Confidence Scoring** — Retrieval confidence calculated from result count
5. **Chunking Consistency** — Legal-domain separators with versioned chunking parameters

---

## 🏗️ RAG Architecture

The pipeline is split across three dedicated services:

```
Document Upload (ingestion)                   User Query (runtime)
       ↓                                           ↓
[RAGService]                               [LLMService]
  1. Load document (PDF/TXT)                  1. Detect language
  2. Split with legal separators              2. Check semantic cache
  3. Generate embeddings (OpenAI)             3. Call RetrievalService
  4. Store DocumentChunk rows                 4. Build system prompt
       ↓                                     5. Call OpenAI LLM
  PostgreSQL (pgvector)                       6. Log telemetry + cache response
                                                   ↓
                                              Streaming response to user
```

## 📥 Document Ingestion (RAGService)

The `RAGService` handles the full ingestion pipeline: document loading, text splitting, embedding generation, and pgvector storage.

### Implementation

```python
# app/application/services/rag_service.py
from langchain_community.document_loaders import PyPDFLoader, TextLoader
from langchain_openai import OpenAIEmbeddings
from langchain_text_splitters import RecursiveCharacterTextSplitter

from app.config import settings
from app.domain.interfaces.document_repository import IDocumentRepository
from app.infrastructure.models.document_chunk import DocumentChunk


class RAGService:
    """Orchestrates LangChain text splitting and OpenAI Vector Embedding."""

    def __init__(self, repository: IDocumentRepository):
        self.repository = repository
        self.embeddings = OpenAIEmbeddings(
            model=settings.OPENAI_EMBEDDING_MODEL,
            api_key=settings.OPENAI_API_KEY
        )

    async def process_and_store_document(
        self, document_id: UUID, storage_path: str, language: str = "English"
    ):
        """Extract text, chunk it, embed it, and store pgvector rows."""

        # 1. Select loader based on file extension
        ext = storage_path.split('.')[-1].lower()
        if ext == 'pdf':
            loader = PyPDFLoader(storage_path)
        elif ext == 'txt':
            loader = TextLoader(storage_path, encoding="utf-8")
        else:
            logger.error(f"Unsupported format for Document {document_id}")
            return

        try:
            # 2. Extract document content
            docs = loader.load()

            # 3. Split with legal-domain separators
            LEGAL_SEPARATORS = [
                "\n\n## ",   # Section headers
                "\n\n### ",  # Subsection headers
                "\n\n",      # Paragraphs
                "\n",        # Lines
                ". ",        # Sentences
                " "          # Words
            ]

            text_splitter = RecursiveCharacterTextSplitter(
                chunk_size=settings.CHUNK_SIZE,      # default: 1000
                chunk_overlap=settings.CHUNK_OVERLAP, # default: 200
                separators=LEGAL_SEPARATORS
            )

            splits = text_splitter.split_documents(docs)
            texts = [s.page_content for s in splits]

            # 4. Generate embeddings (network call to OpenAI)
            vectors = await self.embeddings.aembed_documents(texts)

            # 5. Build DocumentChunk ORM objects
            db_chunks = []
            chunk_total = len(splits)

            for idx, (split, vector) in enumerate(zip(splits, vectors)):
                chunk = DocumentChunk(
                    document_id=document_id,
                    content=split.page_content,
                    language=language,
                    embedding=vector,
                    chunk_index=idx,
                    chunk_total=chunk_total,
                    chunk_size=len(split.page_content),
                    embedding_model=settings.OPENAI_EMBEDDING_MODEL,
                    embedding_version="v3",
                    chunking_version="v1"
                )
                chunk.metadata_ = split.metadata
                db_chunks.append(chunk)

            # 6. Persist to PostgreSQL via repository
            await self.repository.save_chunks(db_chunks)
            await self.repository.update_status(document_id, "Processed")

        except Exception as e:
            await self.repository.update_status(document_id, "Failed")
            logger.error(f"Failed to process document {document_id}: {e}", exc_info=True)
```

### Key Design Decisions

- **Legal separators** — Splits on section headers first, then paragraphs, sentences, and words. This preserves legal document structure.
- **Configurable chunking** — `CHUNK_SIZE` (1000) and `CHUNK_OVERLAP` (200) are from `settings`, not hardcoded.
- **Version tracking** — Every chunk records `embedding_model`, `embedding_version`, and `chunking_version`.
- **Status updates** — Documents are marked `"Processed"` or `"Failed"` via `repository.update_status()`.
- **Metadata preservation** — LangChain document metadata (page numbers, source path) is stored in the `metadata_` JSONB column.

## 🔍 Retrieval Service

The `RetrievalService` handles runtime similarity search with dynamic top-k and confidence scoring.

### Implementation

```python
# app/application/services/retrieval_service.py
from langchain_openai import OpenAIEmbeddings
from app.domain.interfaces.document_repository import IDocumentRepository
from app.domain.interfaces.retrieval_log_repository import IRetrievalLogRepository


class RetrievalService:
    """Centralized document retrieval service with telemetry logging."""

    def __init__(self, repository: IDocumentRepository, log_repository: IRetrievalLogRepository = None):
        self.repository = repository
        self.log_repository = log_repository
        self.embeddings = OpenAIEmbeddings(
            model=settings.OPENAI_EMBEDDING_MODEL,
            api_key=settings.OPENAI_API_KEY
        )

    async def retrieve(
        self,
        query: str,
        language: str = "English",
        threshold: float = 0.7
    ) -> Tuple[List[DocumentChunk], str]:
        """Retrieve relevant document chunks with dynamic top-k."""

        top_k = self._determine_optimal_top_k(query)

        try:
            query_vector = await self.embeddings.aembed_query(query)

            chunks = await self.repository.search_similar_chunks(
                query_vector, limit=top_k, threshold=threshold
            )

            confidence = self._calculate_confidence(chunks, query_vector)

            # Log retrieval telemetry if repository provided
            if self.log_repository:
                await self.log_repository.log_retrieval(
                    conversation_id=None,
                    query=query,
                    language=language,
                    top_k=top_k,
                    retrieved_chunks=[
                        {"chunk_id": c.id, "similarity_score": getattr(c, "similarity", 0.0)}
                        for c in chunks
                    ]
                )

            return chunks, confidence

        except Exception as e:
            logger.error(f"Retrieval failed: {e}", exc_info=True)
            return [], "None"
```

### Dynamic Top-K

The top-k value adapts based on query complexity (word count):

```python
    def _determine_optimal_top_k(self, query: str) -> int:
        """Dynamically determine optimal top_k based on query length."""
        query_length = len(query.split())

        if query_length < 10:
            return 3   # Simple query, few sources needed
        elif query_length > 20:
            return 8   # Complex query, more context needed
        else:
            return 5   # Default
```

### Confidence Scoring

Confidence is calculated from the number of returned chunks (those above the similarity threshold):

```python
    def _calculate_confidence(self, retrieved_docs, query_vector) -> str:
        if not retrieved_docs:
            return "None"
        if len(retrieved_docs) >= 5:
            return "High"
        elif len(retrieved_docs) >= 2:
            return "Medium"
        else:
            return "Low"
```

## 🗄️ Vector Search (Repository Layer)

The `DocumentRepository` implements the actual pgvector query using SQLAlchemy's `cosine_distance` method:

```python
# app/infrastructure/repositories/document_repository.py
class DocumentRepository(IDocumentRepository):

    async def search_similar_chunks(
        self, query_embedding: list[float], limit: int = 5, threshold: float = 0.7
    ) -> List[DocumentChunk]:
        """Uses pgvector's cosine_distance to return the closest chunks.
        A threshold of 0.7 means cosine distance must be < 0.3."""

        max_distance = 1.0 - threshold

        stmt = (
            select(DocumentChunk)
            .where(DocumentChunk.embedding.cosine_distance(query_embedding) < max_distance)
            .order_by(DocumentChunk.embedding.cosine_distance(query_embedding))
            .limit(limit)
        )
        result = await self.session.execute(stmt)
        return list(result.scalars().all())
```

This uses pgvector's native SQLAlchemy integration instead of raw SQL — the `cosine_distance()` method on the `Vector` column compiles to the `<=>` operator.

## 📄 Chunking Configuration

Chunking parameters are configurable via `app/config.py`:

```python
# app/config.py
class Settings(BaseSettings):
    CHUNK_SIZE: int = 1000       # Characters per chunk
    CHUNK_OVERLAP: int = 200     # Overlap between consecutive chunks
    VECTOR_SEARCH_TOP_K: int = 5 # Default retrieval limit
```

### Legal Document Separators

The separator hierarchy preserves legal document structure:

| Priority | Separator | Purpose |
|---|---|---|
| 1 | `\n\n## ` | Section headers |
| 2 | `\n\n### ` | Subsection headers |
| 3 | `\n\n` | Paragraph boundaries |
| 4 | `\n` | Line breaks |
| 5 | `. ` | Sentence boundaries |
| 6 | ` ` | Word boundaries (fallback) |

The splitter tries the highest-priority separator first and falls back to lower priorities if chunks are still too large.

## 🏷️ Citation Format

All prompt templates enforce a consistent citation format:

```
[Source: Act Name, Section Number]
```

Citations are embedded inline by the LLM as instructed by the system prompt. The prompt templates include the rule:

> *"You must strictly cite the exact source Act and Section for every claim using the format [Source: Act Name, Section Number] inline where the claim is made."*

## 📋 Checklist: RAG Pipeline Implementation

✅ **Architecture**

- [ ] `RAGService` handles document ingestion only
- [ ] `RetrievalService` handles similarity search only
- [ ] `LLMService` handles generation only (calls `RetrievalService` internally)
- [ ] Vector search uses `DocumentRepository.search_similar_chunks()`

✅ **Chunking**

- [ ] Using `RecursiveCharacterTextSplitter` from LangChain
- [ ] Legal-domain separators configured (section → paragraph → sentence → word)
- [ ] `CHUNK_SIZE` and `CHUNK_OVERLAP` from settings (not hardcoded)
- [ ] `chunking_version` tracked on every chunk

✅ **Retrieval**

- [ ] Dynamic top-k based on query complexity
- [ ] Similarity threshold enforced (default: 0.7)
- [ ] Confidence scoring returned with results
- [ ] Retrieval telemetry logged via `IRetrievalLogRepository`

✅ **Embeddings**

- [ ] Using `OpenAIEmbeddings` from `langchain_openai`
- [ ] Model: `text-embedding-3-large` (3072 dimensions)
- [ ] `embedding_model` and `embedding_version` stored on every chunk

## 🚨 Common Mistakes to Avoid

❌ **Mixed services**

```python
# BAD — retrieval logic must not live in LLMService
class LLMService:
    def generate(self, query):
        docs = self.vector_db.search(query)  # DON'T MIX!
```

❌ **Inconsistent chunking**

```python
# BAD — use RecursiveCharacterTextSplitter with legal separators
chunks = text.split("\n")  # No overlap, no size control
```

❌ **Hardcoded chunking parameters**

```python
# BAD — use settings.CHUNK_SIZE and settings.CHUNK_OVERLAP
splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
```

❌ **Raw SQL instead of ORM**

```python
# BAD — use DocumentChunk.embedding.cosine_distance() method
sql = text("SELECT * FROM document_chunks ORDER BY embedding <=> :vec")
```
