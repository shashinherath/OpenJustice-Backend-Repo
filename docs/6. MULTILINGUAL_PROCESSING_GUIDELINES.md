# 5️⃣ Multilingual Processing Guidelines

## 📋 Purpose

Handle **Sinhala**, **Tamil**, and **English** reliably in the OpenJustice legal assistance platform. Ensure accurate language detection, proper translation strategy, and language-aware processing.

---

## 🎯 Core Principles

1. **Auto-Detection** - Automatically identify user's language
2. **Native Retrieval** - Search in original language first
3. **Unicode Normalization** - Handle character encoding properly
4. **Language-Specific Chunking** - Respect linguistic boundaries
5. **Fallback Logic** - Graceful degradation when translation fails

## 🔍 Language Detection Rules

Implement reliable language detection for all user inputs to route queries to the appropriate language-specific processing pipeline. Use established libraries (langdetect, fastText) with confidence thresholds. Cache detection results per session to avoid redundant processing. Log detection failures for monitoring and improvement.

### Detection Service

```python
# app/services/language_detection_service.py
from langdetect import detect, DetectorFactory
from typing import Optional
import re

# Set seed for reproducibility
DetectorFactory.seed = 0

class LanguageDetectionService:
    """Detect language of user input"""

    # Language mappings
    SUPPORTED_LANGUAGES = {
        'en': 'English',
        'si': 'Sinhala',
        'ta': 'Tamil'
    }

    DEFAULT_LANGUAGE = 'English'

    @classmethod
    def detect_language(cls, text: str) -> str:
        """Detect language from text"""

        if not text or len(text.strip()) < 3:
            logger.warning("Text too short for detection, using default")
            return cls.DEFAULT_LANGUAGE

        try:
            # Unicode-based detection (more reliable for Sinhala/Tamil)
            language_code = cls._detect_by_unicode(text)

            if language_code:
                return cls.SUPPORTED_LANGUAGES.get(language_code, cls.DEFAULT_LANGUAGE)

            # Fallback to langdetect library
            language_code = detect(text)
            detected = cls.SUPPORTED_LANGUAGES.get(language_code, cls.DEFAULT_LANGUAGE)

            logger.info(f"Detected language: {detected} (code: {language_code})")
            return detected

        except Exception as e:
            logger.error(f"Language detection failed: {e}")
            return cls.DEFAULT_LANGUAGE

    @staticmethod
    def _detect_by_unicode(text: str) -> Optional[str]:
        """Detect language by Unicode character ranges"""

        # Count characters by script
        sinhala_chars = len(re.findall(r'[\u0D80-\u0DFF]', text))
        tamil_chars = len(re.findall(r'[\u0B80-\u0BFF]', text))
        latin_chars = len(re.findall(r'[a-zA-Z]', text))

        total_chars = sinhala_chars + tamil_chars + latin_chars

        if total_chars == 0:
            return None

        # Calculate percentages
        sinhala_pct = sinhala_chars / total_chars
        tamil_pct = tamil_chars / total_chars
        latin_pct = latin_chars / total_chars

        # Determine language (30% threshold)
        if sinhala_pct > 0.3:
            return 'si'
        elif tamil_pct > 0.3:
            return 'ta'
        elif latin_pct > 0.5:
            return 'en'

        return None

    @classmethod
    def is_multilingual(cls, text: str) -> bool:
        """Check if text contains multiple languages"""

        sinhala = bool(re.search(r'[\u0D80-\u0DFF]', text))
        tamil = bool(re.search(r'[\u0B80-\u0BFF]', text))
        latin = bool(re.search(r'[a-zA-Z]', text))

        # Count how many scripts are present
        script_count = sum([sinhala, tamil, latin])

        return script_count > 1
```

## 🔄 Translation vs Native Retrieval Strategy

Decide whether to translate queries to English for retrieval or use native language embeddings. Translation can work when English documents dominate, but native retrieval is better when you have documents in multiple languages. Hybrid approaches can combine both strategies based on document availability.

### Strategy Decision Tree

```
User Query (Language X)
    ↓
[Native Documents Available?]
    ↓ Yes                    ↓ No
Native Retrieval      Translation Required
    ↓                         ↓
Generate in X         Translate Query → Retrieve → Translate Results
```

### Implementation

Implement the retrieval strategy decision logic based on query language and document availability. Prefer native language retrieval when possible for better semantic matching. Fall back to translation when native documents are unavailable. Track which strategy is used for each query for evaluation.

```python
# app/services/multilingual_rag_service.py

class MultilingualRAGService:
    """RAG with multilingual support"""

    def __init__(self, db: AsyncSession):
        self.retrieval_service = RetrievalService(db)
        self.translation_service = TranslationService()
        self.llm_service = LLMService()

    async def process_query(
        self,
        query: str,
        language: str
    ) -> dict:
        """Process query with language-aware retrieval"""

        # Step 1: Check native document availability
        native_docs_available = await self._check_native_documents(language)

        if native_docs_available:
            logger.info(f"Using native retrieval for {language}")
            return await self._native_retrieval_pipeline(query, language)
        else:
            logger.info(f"Using translation pipeline for {language}")
            return await self._translation_pipeline(query, language)

    async def _native_retrieval_pipeline(
        self,
        query: str,
        language: str
    ) -> dict:
        """Retrieve in native language (preferred)"""

        # Retrieve documents in user's language
        docs = await self.retrieval_service.retrieve(
            query=query,
            language=language,
            top_k=5
        )

        # Generate response in same language
        response = await self.llm_service.generate_legal_response(
            query=query,
            context=self._assemble_context(docs),
            language=language
        )

        return {
            "answer": response['content'],
            "method": "native_retrieval",
            "language": language
        }

    async def _translation_pipeline(
        self,
        query: str,
        source_language: str
    ) -> dict:
        """Translate → Retrieve → Translate back"""

        # Translate query to English (document language)
        translated_query = await self.translation_service.translate(
            text=query,
            source_lang=source_language,
            target_lang="English"
        )

        logger.info(f"Translated query: {translated_query}")

        # Retrieve English documents
        docs = await self.retrieval_service.retrieve(
            query=translated_query,
            language="English",
            top_k=5
        )

        # Generate response in English
        english_response = await self.llm_service.generate_legal_response(
            query=translated_query,
            context=self._assemble_context(docs),
            language="English"
        )

        # Translate response back to user's language
        final_response = await self.translation_service.translate(
            text=english_response['content'],
            source_lang="English",
            target_lang=source_language
        )

        return {
            "answer": final_response,
            "method": "translation_pipeline",
            "language": source_language,
            "original_query": translated_query
        }

    async def _check_native_documents(self, language: str) -> bool:
        """Check if native language documents exist"""

        count = await self.db.execute(
            text("SELECT COUNT(*) FROM documents WHERE language = :lang"),
            {"lang": language}
        )

        return count.scalar() > 0
```

## 📝 Language-Aware Chunking

Different languages have different sentence boundaries and text structures. Use language-specific tokenizers for Sinhala and Tamil rather than generic Unicode splitting. Respect linguistic boundaries to maintain semantic coherence in chunks. This improves both retrieval quality and citation accuracy.

### Sinhala/Tamil Sentence Tokenization

```python
# app/utils/text_utils.py
import re
from typing import List

class MultilingualTextProcessor:
    """Language-aware text processing"""

    # Sentence delimiters by language
    SENTENCE_ENDINGS = {
        'English': ['.', '!', '?'],
        'Sinhala': ['෴', '.', '!', '?'],  # Sinhala kunddaliya
        'Tamil': ['.', '!', '?']
    }

    @classmethod
    def split_sentences(cls, text: str, language: str) -> List[str]:
        """Split text into sentences respecting language rules"""

        if language not in cls.SENTENCE_ENDINGS:
            language = 'English'

        delimiters = cls.SENTENCE_ENDINGS[language]

        # Create regex pattern
        pattern = '|'.join(re.escape(d) for d in delimiters)

        # Split and clean
        sentences = re.split(f'({pattern})', text)

        # Recombine sentences with their delimiters
        result = []
        for i in range(0, len(sentences), 2):
            if i + 1 < len(sentences):
                sentence = sentences[i] + sentences[i + 1]
            else:
                sentence = sentences[i]

            sentence = sentence.strip()
            if sentence:
                result.append(sentence)

        return result

    @classmethod
    def estimate_token_count(cls, text: str, language: str) -> int:
        """Estimate token count (language-specific)"""

        if language == 'English':
            # English: ~0.75 words per token
            words = len(text.split())
            return int(words / 0.75)

        elif language in ['Sinhala', 'Tamil']:
            # Sinhala/Tamil: ~1 character per token (approx)
            return len(text)

        else:
            # Default
            return len(text.split())
```

### Language-Aware Document Chunker

Build a chunker that detects document language and applies appropriate tokenization logic. Use character-based chunking for Sinhala/Tamil and word-based for English. Adjust chunk sizes based on script density and information content per character.

```python
# app/services/multilingual_chunker.py

class MultilingualChunker:
    """Chunk documents respecting language boundaries"""

    def __init__(self):
        self.text_processor = MultilingualTextProcessor()

    def chunk_document(
        self,
        text: str,
        language: str,
        metadata: dict
    ) -> List[dict]:
        """Chunk document with language-aware splitting"""

        # Split into sentences first
        sentences = self.text_processor.split_sentences(text, language)

        chunks = []
        current_chunk = []
        current_token_count = 0

        max_tokens = 500
        overlap_tokens = 50

        for sentence in sentences:
            sentence_tokens = self.text_processor.estimate_token_count(sentence, language)

            if current_token_count + sentence_tokens > max_tokens and current_chunk:
                # Save current chunk
                chunk_text = ' '.join(current_chunk)
                chunks.append({
                    "content": chunk_text,
                    "metadata": {
                        **metadata,
                        "chunk_index": len(chunks),
                        "language": language
                    }
                })

                # Start new chunk with overlap
                overlap_sentences = current_chunk[-2:] if len(current_chunk) >= 2 else current_chunk
                current_chunk = overlap_sentences + [sentence]
                current_token_count = sum(
                    self.text_processor.estimate_token_count(s, language)
                    for s in current_chunk
                )
            else:
                current_chunk.append(sentence)
                current_token_count += sentence_tokens

        # Add final chunk
        if current_chunk:
            chunks.append({
                "content": ' '.join(current_chunk),
                "metadata": {
                    **metadata,
                    "chunk_index": len(chunks),
                    "language": language
                }
            })

        return chunks
```

## 🔤 Unicode Normalization

Unicode text can represent the same character in multiple ways (combining marks, precomposed characters). Normalize all text to NFC (Canonical Composition) form to ensure consistent matching and embeddings. This is especially important for Sinhala and Tamil which use complex combining character sequences.

### Normalization Rules

```python
# app/core/unicode_normalizer.py
import unicodedata

class UnicodeNormalizer:
    """Normalize Unicode text for consistency"""

    @staticmethod
    def normalize(text: str, form: str = 'NFC') -> str:
        """
        Normalize Unicode text.

        Forms:
        - NFC: Canonical Decomposition + Canonical Composition (PREFERRED)
        - NFD: Canonical Decomposition
        - NFKC: Compatibility Decomposition + Canonical Composition
        - NFKD: Compatibility Decomposition
        """

        if not text:
            return text

        # Normalize to NFC (most compact, recommended for storage)
        normalized = unicodedata.normalize(form, text)

        return normalized

    @staticmethod
    def remove_diacritics(text: str) -> str:
        """Remove diacritical marks (use cautiously!)"""

        # Decompose
        nfd = unicodedata.normalize('NFD', text)

        # Filter out combining characters
        output = ''.join(
            char for char in nfd
            if unicodedata.category(char) != 'Mn'
        )

        return unicodedata.normalize('NFC', output)

    @staticmethod
    def is_valid_unicode(text: str) -> bool:
        """Check if text contains valid Unicode"""

        try:
            text.encode('utf-8').decode('utf-8')
            return True
        except (UnicodeEncodeError, UnicodeDecodeError):
            return False
```

### Applying Normalization

Apply Unicode normalization at input boundaries: when receiving user queries, ingesting documents, and before embedding generation. Normalize consistently across all pipelines to ensure text matching works correctly. Store normalized text but keep original for display.

```python
# app/services/document_processor.py

async def process_document(self, file_content: str, language: str) -> dict:
    """Process document with Unicode normalization"""

    # Step 1: Validate Unicode
    if not UnicodeNormalizer.is_valid_unicode(file_content):
        raise ValidationException("Document contains invalid Unicode characters")

    # Step 2: Normalize
    normalized_text = UnicodeNormalizer.normalize(file_content, form='NFC')

    logger.info(f"Normalized {language} document: "
               f"{len(file_content)} → {len(normalized_text)} bytes")

    # Step 3: Chunk
    chunks = self.multilingual_chunker.chunk_document(
        text=normalized_text,
        language=language,
        metadata={"source": "uploaded_document"}
    )

    return {"chunks": chunks, "language": language}
```

## 🔀 Fallback Language Logic

Define clear fallback behavior when language detection fails or requested language resources are unavailable. Default to English as the primary fallback, then to the user's last known language preference. Always inform users when fallback is applied so they understand potential limitations.

### Fallback Strategy

```python
# app/services/fallback_service.py

class FallbackLanguageService:
    """Handle fallback when language processing fails"""

    # Fallback chain: User Language → English → Generic Response

    async def process_with_fallback(
        self,
        query: str,
        preferred_language: str
    ) -> dict:
        """Process query with fallback chain"""

        attempts = []

        # Attempt 1: Preferred language
        try:
            result = await self.rag_service.process_query(
                query=query,
                language=preferred_language
            )

            attempts.append({
                "method": "native",
                "language": preferred_language,
                "status": "success"
            })

            return self._format_response(result, attempts)

        except Exception as e:
            logger.warning(f"Native processing failed: {e}")
            attempts.append({
                "method": "native",
                "language": preferred_language,
                "status": "failed",
                "error": str(e)
            })

        # Attempt 2: English fallback
        if preferred_language != "English":
            try:
                result = await self.rag_service.process_query(
                    query=query,
                    language="English"
                )

                # Translate response back
                translated = await self.translation_service.translate(
                    text=result['answer'],
                    source_lang="English",
                    target_lang=preferred_language
                )

                attempts.append({
                    "method": "english_fallback",
                    "language": "English",
                    "status": "success"
                })

                result['answer'] = translated
                return self._format_response(result, attempts)

            except Exception as e:
                logger.error(f"English fallback failed: {e}")
                attempts.append({
                    "method": "english_fallback",
                    "language": "English",
                    "status": "failed",
                    "error": str(e)
                })

        # Attempt 3: Generic response
        generic_response = self._get_generic_response(preferred_language)
        attempts.append({
            "method": "generic",
            "status": "success"
        })

        return self._format_response(
            {"answer": generic_response},
            attempts
        )

    def _get_generic_response(self, language: str) -> str:
        """Get generic fallback response"""

        responses = {
            "English": "I'm sorry, I couldn't process your request. Please try rephrasing your question or contact support.",
            "Sinhala": "මට ඔබගේ ඉල්ලීම සැකසීමට නොහැකි විය. කරුණාකර ඔබේ ප්‍රශ්නය නැවත සකස් කරන්න හෝ සහාය අමතන්න.",
            "Tamil": "மன்னிக்கவும், உங்கள் கோரிக்கையை நான் செயலாக்க முடியவில்லை. தயவுசெய்து உங்கள் கேள்வியை மறுவரையறை செய்யவும் அல்லது ஆதரவைத் தொடர்பு கொள்ளவும்."
        }

        return responses.get(language, responses["English"])

    @staticmethod
    def _format_response(result: dict, attempts: list) -> dict:
        """Format response with attempt history"""
        return {
            **result,
            "fallback_chain": attempts,
            "final_method": attempts[-1]['method']
        }
```

## 📊 Language-Specific Evaluation Metrics

Evaluate retrieval and generation quality separately for each language. Metrics like BLEU, ROUGE, and semantic similarity may need language-specific tuning. Build test sets for each language with native speaker validation. Track per-language performance to identify gaps and prioritize improvements.

### Multilingual Quality Assessment

```python
# app/evaluation/multilingual_metrics.py

class MultilingualMetrics:
    """Evaluate responses across languages"""

        english_response: str,
        translated_response: str,
        target_language: str
    ) -> float:

        # Compare with original English
        similarity = calculate_semantic_similarity(english_response, back_translation)

    @staticmethod

        original: str,
        translated: str
```
