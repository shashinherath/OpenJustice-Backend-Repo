# 4️⃣ Vector Database & Embedding Guidelines

## 📋 Purpose

Maintain **consistency** and **reproducibility** in vector search operations using **pgvector**. Ensure embedding lifecycle management, immutability, and proper indexing strategies.

---

## 🎯 Core Principles

1. **Immutability** - Embeddings never change after creation
2. **Versioning** - Track embedding model versions
3. **Single Distance Metric** - Cosine similarity only
4. **Schema Consistency** - Standardized vector table structure
5. **Cleanup Strategy** - Orphaned vector removal

## 🗄️ pgvector Schema Rules

Define a consistent schema for storing embeddings in PostgreSQL with pgvector extension. Include metadata columns for document tracking, embedding model version, and creation timestamps. Use appropriate indexing strategies (IVFFlat or HNSW) based on dataset size and query performance requirements.

### Standard Vector Table Schema

```sql
-- migrations/001_create_document_chunks.sql

-- Enable pgvector extension
CREATE EXTENSION IF NOT EXISTS vector;

-- Document chunks table with vectors
CREATE TABLE document_chunks (
    id SERIAL PRIMARY KEY,
    document_id INTEGER NOT NULL REFERENCES documents(id) ON DELETE CASCADE,

    -- Content
    content TEXT NOT NULL,
    language VARCHAR(20) NOT NULL DEFAULT 'English',

    -- Vector embedding (1536 dimensions for OpenAI text-embedding-3-small)
    embedding vector(1536) NOT NULL,

    -- Metadata
    metadata JSONB DEFAULT '{}',

    -- Chunk information
    chunk_index INTEGER NOT NULL,
    chunk_total INTEGER NOT NULL,
    chunk_size INTEGER NOT NULL,

    -- Versioning
    embedding_model VARCHAR(100) NOT NULL,
    embedding_version VARCHAR(20) NOT NULL,
    chunking_version VARCHAR(20) NOT NULL DEFAULT 'v1',

    -- Timestamps
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),

    -- Constraints
    CONSTRAINT valid_chunk_index CHECK (chunk_index >= 0),
    CONSTRAINT valid_chunk_size CHECK (chunk_size > 0)
);

-- Indexes for performance
CREATE INDEX idx_document_chunks_document_id ON document_chunks(document_id);
CREATE INDEX idx_document_chunks_language ON document_chunks(language);
CREATE INDEX idx_document_chunks_embedding_model ON document_chunks(embedding_model);

-- Vector index using HNSW (Hierarchical Navigable Small World)
-- Using cosine distance (1 - cosine_similarity)
CREATE INDEX idx_document_chunks_embedding
ON document_chunks
USING hnsw (embedding vector_cosine_ops);

-- Metadata indexes (for filtering)
CREATE INDEX idx_document_chunks_metadata ON document_chunks USING gin(metadata);
```

### SQLAlchemy Model

Implement the vector table schema using SQLAlchemy ORM with pgvector integration. Define the embedding column with proper vector dimensionality matching your embedding model (e.g., 1536 for text-embedding-ada-002). Include all necessary metadata columns for tracking and auditing.

```python
# app/models/document_chunk.py
from sqlalchemy import Column, Integer, String, Text, DateTime, ForeignKey, CheckConstraint
from sqlalchemy.dialects.postgresql import JSONB
from pgvector.sqlalchemy import Vector
from datetime import datetime
from app.db.base import Base

class DocumentChunk(Base):
    """Document chunk with vector embedding"""
    __tablename__ = "document_chunks"

    id = Column(Integer, primary_key=True, index=True)
    document_id = Column(Integer, ForeignKey("documents.id", ondelete="CASCADE"), nullable=False)

    # Content
    content = Column(Text, nullable=False)
    language = Column(String(20), nullable=False, default="English")

    # Vector embedding (1536 dimensions)
    embedding = Column(Vector(1536), nullable=False)

    # Metadata
    metadata = Column(JSONB, default={})

    # Chunk information
    chunk_index = Column(Integer, nullable=False)
    chunk_total = Column(Integer, nullable=False)
    chunk_size = Column(Integer, nullable=False)

    # Versioning (CRITICAL for reproducibility)
    embedding_model = Column(String(100), nullable=False)
    embedding_version = Column(String(20), nullable=False)
    chunking_version = Column(String(20), nullable=False, default="v1")

    # Timestamps
    created_at = Column(DateTime, default=datetime.utcnow)
    updated_at = Column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)

    # Constraints
    __table_args__ = (
        CheckConstraint('chunk_index >= 0', name='valid_chunk_index'),
        CheckConstraint('chunk_size > 0', name='valid_chunk_size'),
    )

    def __repr__(self):
        return f"<DocumentChunk(id={self.id}, doc_id={self.document_id}, chunk={self.chunk_index}/{self.chunk_total})>"
```

## 📏 Distance Metrics (Cosine Only)

Always use cosine distance (1 - cosine similarity) for vector similarity search. Cosine distance is normalized, making it ideal for comparing semantic similarity regardless of vector magnitude. Never mix distance metrics—inconsistent metrics lead to unreproducible results and ranking issues.

### Why Cosine Similarity?

- **Normalized vectors** - Magnitude-independent
- **Semantic similarity** - Best for text embeddings
- **Consistent results** - Reproducible across queries
- **Industry standard** - OpenAI embeddings are normalized

### Distance Metric Policy

```python
# app/config.py
class Settings(BaseSettings):
```

### Using Cosine Distance in Queries

Use pgvector's `<=>` operator for cosine distance queries. Always order by distance ascending (smaller distance = higher similarity). Include distance scores in results for transparency and confidence calculation.

```python
# app/repositories/vector_repository.py
from sqlalchemy import text
from typing import List

class VectorRepository:
    """Vector search operations"""

    async def search_similar(
        self,
        query_embedding: List[float],
        top_k: int = 5,
        threshold: float = 0.7
    ) -> List[DocumentChunk]:
        """Search similar vectors using cosine distance"""

        # pgvector cosine distance: 1 - cosine_similarity
        # Lower distance = more similar
        # Convert to similarity: 1 - distance

        sql = text("""
            SELECT
                *,
                1 - (embedding <=> :query_embedding) as similarity
            FROM document_chunks
            WHERE 1 - (embedding <=> :query_embedding) > :threshold
            ORDER BY embedding <=> :query_embedding
            LIMIT :top_k
        """)

        result = await self.db.execute(
            sql,
            {
                "query_embedding": str(query_embedding),
                "threshold": threshold,
                "top_k": top_k
            }
        )

        return result.fetchall()
```

## 🔒 Embedding Immutability

Once created, embedding vectors must never be modified in place. Embeddings represent the semantic meaning of text at a specific point in time with a specific model. Changing them would break reproducibility and invalidate past retrieval results. Always create new records with new embeddings when content changes.

### Rule: Embeddings NEVER Change

```python
# app/models/document_chunk.py

class DocumentChunk(Base):
    # ...

    @validates('embedding')
    def validate_embedding_immutable(self, key, value):
        """Prevent embedding modification after creation"""
        if self.id is not None and self.embedding is not None:
            raise ValueError(
                "Embeddings are immutable. Create a new chunk instead of updating."
            )
        return value
```

### Updating Documents

When document content changes, create a new embedding record and mark the old one as obsolete. Never update the embedding column directly. This preserves historical data for auditing and enables rollback if needed.

```python

async def update_document(doc_id: int, new_text: str):
    # Mark old chunks as archived
    old_chunks = await get_chunks(doc_id)
```

## 🔄 Re-indexing Policies

Re-indexing (regenerating all embeddings) is necessary when changing embedding models, chunking strategies, or preprocessing logic. Re-indexing is expensive and disruptive, so plan carefully with proper versioning and blue-green deployment strategies. Never re-index in place—always create new version tables.

### When to Re-index

```python
# app/services/vector_reindex_service.py

class VectorReindexService:
    """Manage vector re-indexing operations"""

    # Re-indexing triggers
    REINDEX_TRIGGERS = [
        "embedding_model_upgrade",  # New OpenAI model
        "chunking_strategy_change",  # New chunking algorithm
        "data_corruption_detected",  # Data integrity issues
        "performance_degradation"   # Index optimization
    ]

    async def should_reindex(self) -> dict:
        """Determine if re-indexing is needed"""

        # Check for model version mismatch
        current_model = settings.OPENAI_EMBEDDING_MODEL
        db_models = await self.get_unique_embedding_models()

        if len(db_models) > 1:
            return {
                "should_reindex": True,
                "reason": "multiple_embedding_models",
                "details": f"Found models: {db_models}, current: {current_model}"
            }

        # Check for chunking version mismatch
        current_chunking = "v1"
        db_chunking = await self.get_unique_chunking_versions()

        if current_chunking not in db_chunking:
            return {
                "should_reindex": True,
                "reason": "chunking_version_mismatch",
                "details": f"DB versions: {db_chunking}, current: {current_chunking}"
            }

        return {"should_reindex": False}

    async def reindex_all_documents(self):
        """Re-index all documents with new embeddings"""

        logger.warning("Starting full re-index - this may take a while")

        # Get all documents
        documents = await self.document_repository.list_all()

        total = len(documents)
        for i, doc in enumerate(documents, 1):
            try:
                logger.info(f"Re-indexing document {i}/{total}: {doc.id}")

                # Delete old chunks
                await self.delete_document_chunks(doc.id)

                # Create new chunks with current model
                await self.create_document_chunks(
                    document_id=doc.id,
                    text=doc.content,
                    embedding_model=settings.OPENAI_EMBEDDING_MODEL,
                    chunking_version="v1"
                )

                await self.db.commit()

            except Exception as e:
                logger.error(f"Failed to re-index document {doc.id}: {e}")
                await self.db.rollback()

        logger.info(f"Re-indexing complete: {total} documents processed")
```

### Safe Re-indexing Strategy

Implement blue-green re-indexing: create a new table version, populate it with new embeddings, test thoroughly, then switch traffic atomically. Keep the old version available for rollback. This ensures zero downtime and safe deployments.

```python
async def safe_reindex_with_rollback(self):
    """Re-index with ability to rollback"""

    # Step 1: Create shadow table
    await self.create_shadow_table()

    # Step 2: Index into shadow table
    await self.reindex_to_shadow_table()

    # Step 3: Validate shadow table
    validation_passed = await self.validate_shadow_table()

    if validation_passed:
        # Step 4: Swap tables atomically
        await self.swap_tables()
        logger.info("Re-indexing successful, shadow table promoted")
    else:
        # Rollback: Drop shadow table
        await self.drop_shadow_table()
        logger.error("Re-indexing validation failed, rolled back")
```

## 📦 Versioned Embedding Models

Track which embedding model version generated each vector. This is critical for reproducibility and troubleshooting. Store model name, version, and configuration in metadata. Different model versions produce incompatible embeddings that cannot be compared directly.

### Model Version Tracking

```python
# app/services/embedding_service.py
from typing import List
import hashlib

class EmbeddingService:
    """Generate and manage embeddings"""

    # Embedding model registry
    EMBEDDING_MODELS = {
        "v1": {
            "name": "text-embedding-3-small",
            "dimensions": 1536,
            "provider": "openai",
            "version": "3"
        },
        "v2": {
            "name": "text-embedding-3-large",
            "dimensions": 3072,
            "provider": "openai",
            "version": "3"
        }
    }

    def __init__(self):
        self.current_version = "v1"
        self.model_config = self.EMBEDDING_MODELS[self.current_version]
        self.client = AsyncOpenAI(api_key=settings.OPENAI_API_KEY)

    async def embed_text(self, text: str) -> List[float]:
        """Generate embedding with version tracking"""

        # Normalize text
        text = text.strip()

        if not text:
            raise ValueError("Cannot embed empty text")

        # Generate embedding
        response = await self.client.embeddings.create(
            input=text,
            model=self.model_config["name"]
        )

        embedding = response.data[0].embedding

        # Validate dimensions
        if len(embedding) != self.model_config["dimensions"]:
            raise ValueError(
                f"Embedding dimension mismatch: expected {self.model_config['dimensions']}, "
                f"got {len(embedding)}"
            )

        logger.debug(f"Generated embedding: model={self.model_config['name']}, "
                    f"dimensions={len(embedding)}")

        return embedding

    def get_model_metadata(self) -> dict:
        """Get current model metadata"""
        return {
            "version": self.current_version,
            "model_name": self.model_config["name"],
            "dimensions": self.model_config["dimensions"],
            "provider": self.model_config["provider"]
        }
```

### Storing Embeddings with Metadata

Always store embedding model information alongside the vector. Include model name, version, and embedding dimension. This metadata enables validation, migration between models, and debugging of retrieval issues.

```python
async def create_document_chunk_with_embedding(
    self,
    content: str,
    document_id: int,
    metadata: dict
) -> DocumentChunk:
    """Create chunk with embedding and version metadata"""

    # Generate embedding
    embedding = await self.embedding_service.embed_text(content)

    # Get model metadata
    model_metadata = self.embedding_service.get_model_metadata()

    # Create chunk
    chunk = DocumentChunk(
        document_id=document_id,
        content=content,
        embedding=embedding,
        metadata=metadata,

        # Version tracking (CRITICAL)

        embedding_version=model_metadata['version'],
        chunking_version="v1"
    )

    self.db.add(chunk)
    await self.db.commit()
    await self.db.refresh(chunk)

    return chunk
```

## 🧹 Vector Cleanup Strategy

Regularly clean up obsolete and orphaned embeddings to manage database size and query performance. Identify embeddings whose source documents no longer exist or have been marked as deleted. Implement scheduled cleanup jobs with proper logging and safeguards.

### Orphaned Vector Detection

```python
# app/services/vector_cleanup_service.py

class VectorCleanupService:
    """Clean up orphaned and archived vectors"""

    async def find_orphaned_chunks(self) -> List[int]:
        """Find chunks referencing deleted documents"""

        sql = text("""
            SELECT dc.id
            FROM document_chunks dc
            LEFT JOIN documents d ON dc.document_id = d.id
            WHERE d.id IS NULL
        """)

        result = await self.db.execute(sql)
        orphaned_ids = [row.id for row in result.fetchall()]

        logger.info(f"Found {len(orphaned_ids)} orphaned chunks")
        return orphaned_ids

    async def find_archived_chunks(self, older_than_days: int = 30) -> List[int]:
        """Find archived chunks older than threshold"""

        sql = text("""
            SELECT id
            FROM document_chunks
            WHERE metadata->>'archived' = 'true'
            AND (metadata->>'archived_at')::timestamp < NOW() - :days * INTERVAL '1 day'
        """)

        result = await self.db.execute(sql, {"days": older_than_days})
        archived_ids = [row.id for row in result.fetchall()]

        logger.info(f"Found {len(archived_ids)} archived chunks older than {older_than_days} days")
        return archived_ids

    async def delete_chunks_batch(self, chunk_ids: List[int], batch_size: int = 100):
        """Delete chunks in batches"""

        total = len(chunk_ids)
        for i in range(0, total, batch_size):
            batch = chunk_ids[i:i+batch_size]

            sql = text("DELETE FROM document_chunks WHERE id = ANY(:ids)")
            await self.db.execute(sql, {"ids": batch})
            await self.db.commit()

            logger.info(f"Deleted batch {i//batch_size + 1}: {len(batch)} chunks")

    async def cleanup_old_vectors(self):
        """Run full cleanup process"""

        # Find orphaned chunks
        orphaned = await self.find_orphaned_chunks()

        # Find archived chunks
        archived = await self.find_archived_chunks(older_than_days=30)

        # Combine and deduplicate
        to_delete = list(set(orphaned + archived))

        if to_delete:
            logger.warning(f"Deleting {len(to_delete)} chunks")
            await self.delete_chunks_batch(to_delete)
        else:
            logger.info("No chunks to delete")
```

### Scheduled Cleanup Task

Implement automated cleanup as a scheduled background job. Run during low-traffic periods and include dry-run mode for safety. Log all deletions for auditing. Use soft deletes first before hard deleting to enable recovery if mistakes are made.

```python
# app/tasks/vector_cleanup_task.py
from apscheduler.schedulers.asyncio import AsyncIOScheduler

def schedule_vector_cleanup():
    """Schedule weekly vector cleanup"""

    scheduler = AsyncIOScheduler()

    # Run every Sunday at 2 AM
    scheduler.add_job(
        func=run_vector_cleanup,
        trigger='cron',
        day_of_week='sun',
        hour=2,
        minute=0
    )

    scheduler.start()
    logger.info("Vector cleanup scheduled: Every Sunday at 2 AM")

async def run_vector_cleanup():
    """Execute cleanup task"""
```
